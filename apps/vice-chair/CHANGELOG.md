# 變更紀錄

## 2026-08-31－Codex 細部審視可正式保存

- 月度分析審閱新增「保存 Codex 細部審視」入口，讓副主席可把本次由 Codex 依 BNI 分析 Skill 完成的六區關懷報告保存到正式草稿，不必改用另一家外部模型重做判讀。
- 後端只接受已通過來源對帳、1,200 至 40,000 字元、恰含六個 Markdown 區段，且明載「草稿／副主席確認」的繁體中文報告；保存後仍須副主席明確確認才可發佈版本化快照。
- Codex 審視只引用引擎結構化結果，不重算分數、不修改燈號、不把審計線索當成結論；既有個人 AI API 審視流程仍保留。

## 2026-08-31－v1.0.18 期中關懷跨月延續與月末資料驗收

- 同一會籍週期已有未完成期中關懷任務時，即使超過原 5–7 個月窗口，仍會在後續每月儀表板標示「跨月延續・完成前持續關懷」；沿用原案件、不重複開案，完成後才移除。
- 舊會籍週期任務不帶入復會新週期；PALMS、燈號、審計與其他關懷訊號仍各自依正式資料判定。
- 每月資料更新以台北日期換期；月末當天可提前驗收已完整出齊的當月半年、全年、單月 PALMS 與每週審計，其他日期維持每月 1 日切換上月。
- 補齊 Admin 的首頁每月資料上傳入口；後端原有副主席／Admin 權限與檔案期間驗證維持不變。
- 正式分析新增單月 PALMS 完整性與來源指紋核對；未改動 BNI 計分公式、燈號門檻或既有已發布快照。

## 2026-08-31－v1.0.17 複製文案即可推進三長群與公告階段

- 「複製三長群文案」在剪貼簿成功後會同步把三長群步驟保存至 Supabase，效果等同直接登記完成，接著即可填寫董事顧問確認。
- 董事顧問同意後，「複製公告文案」會登記由副主席人工貼至正式公告群，效果等同 Bot 發送完成；不消耗 LINE Push 額度，成功保存後即可結案。
- 兩個複製動作仍由後端核對副主席權限、正式投票決議、董顧狀態與最新案件 revision；剪貼簿或後端任一步失敗都不會假解鎖。
- 人工複製路徑保存操作人、時間、完成方式與案件歷程；Bot 自動發送路徑維持不變，兩種方式只會完成同一個流程階段。
- 本次不追溯猜測舊版曾複製但未登記的操作，也不修改既有案件、票數、回饋、Word 或董顧內容；舊版已人工貼出的案件只需在新版再按一次複製，即可保存完成紀錄。

## 2026-08-31－v1.0.16 董顧確認與結案解鎖修正

- 修正三長群步驟尚在背景同步時就先解鎖董顧欄位，稍後被伺服器狀態洗回「尚未回覆」的競速問題；三長群步驟現在於 Supabase 成功後才解鎖董顧確認。
- 董顧確認改用獨立後端動作，只更新最新正式案件的確認狀態與備註；一般欄位自動保存不能再覆寫三長群或董顧紀錄。
- 前端等待後端成功後才顯示已保存；失敗、版本衝突或前置步驟不符時直接顯示原因，不再先跳成功提示。
- 結案區新增鎖定原因：通過案件提示先完成正式公告群，不通過案件提示可直接結案；維持董顧實際回覆及人工結案規則。
- 本次不改寫任何既有案件、回饋、正式票、資格快照、Word、公告或結案資料；既有未保存狀態須由副主席在新版頁面重新確認。

## 2026-08-31－v1.0.15 新會員繳費後協助群文稿

- 「常用資源 → 文稿範本」新增「繳費後協助群開場與訪談邀約」，清楚標示前置為新會員已完成申請表與繳費，且秘財已建立主席、副主席、秘財與新會員的協助群。
- 同一項目拆成「＠ 新會員並自我介紹」與「待新會員回覆後邀約入會訪談」兩個獨立複製按鈕，避免把內部步驟標題一併貼到 LINE。
- 自我介紹文案會依當屆副主席名單與會員主檔自動套用姓名、行業別；資料缺漏時保留明確提示，不猜測或寫死現任人選。
- 新文稿仍只供副主席／Admin 查看與複製，不讀取新會員案件、申請表、繳費明細、投票或 Word，也不自動發送 LINE。

## 2026-08-29－v1.0.14 測試群圖卡可改發正式群

- 正式案件的回饋或投票圖卡先在測試群完成 Bot 回覆後，不再整筆鎖死；副主席可按「改發正式群並複製新文案」，再把新文案貼到正式群。
- 改發採單向流程，只允許測試群轉正式群；正式群圖卡回覆後仍維持鎖定，不提供正式轉測試或再次重建連結。
- 改發時撤銷測試群舊連結，避免同一案件同時存在兩個可用入口；測試群已收到的正式回饋或正式票全部保留，未完成者可從正式群新圖卡繼續。
- 新增 `feedback_call.promoted`／`vote_call.promoted` 稽核事件；不刪除、改寫既有案件、回饋、票數、資格快照、Word 或結案紀錄。

## 2026-08-28－v1.0.13 LINE 免登入委員回饋

- 案件頁新增「啟動回饋流程並複製文案」，可選會員委員會測試群或正式群；副主席將完整公版貼到指定群後，會員委員秘書Bot以免費 Reply API 回覆真正 @所有人通知及 Flex 回饋圖卡，不再為每案回饋消耗 Push 額度。
- 新增免登入回饋頁：委員自行選擇姓名並送出，內容直接寫入既有正式 `case_feedback`；測試群只改變圖卡位置，不建立測試資料。
- 依產品決策，頁面一打開就顯示目前所有委員回饋，不要求先送出自己的內容；資料每 20 秒更新，也可手動重新整理。
- 同一姓名的本人回饋不可由公開頁重複覆蓋；若目前只有副主席代填，本人可送出並取代代填版本。申請者迴避、有效名單、案件開放與結案鎖定仍由後端執行。
- 送出完成後提供 LINE 分享與複製，方便把內容貼回委員群延續討論；系統保存不依賴分享是否完成。
- 新增 `case_feedback_calls` 與名單快照、一次性 Token／完整文案雜湊、指定群驗證及 Reply 防重送。Webhook不保存一般群聊或命中文案全文，既有投票、具名票向與結果圖流程不變。

## 2026-08-28－v1.0.12 正式投票可選測試群／正式群發布

- 正式案件的「啟動投票流程並複製文案」新增發布群組選擇，預設正式群，也可明確選擇會員委員會測試群。
- 測試群只改變 Bot 回覆圖卡的位置；呼喚仍固定為 `is_test = false`，委員送票寫入同一份正式 `votes`、資格快照、票數、決議與結案流程。
- 選擇測試群前會顯示二次確認，清楚指出這是正式投票；資料庫及 API 只接受 `test`／`production` 兩種已核對的 `committee` 目的地，不接受前端傳入群組 ID。
- LINE Webhook 只在該呼喚綁定的群組驗證一次性 Token 與完整文案指紋；貼到另一個群組不會回覆圖卡。
- 無登入投票頁接受由測試群或正式群回覆的正式案件連結，兩者均呼叫既有 `edge_cast_public_case_vote`，不恢復任何測試票寫入路徑。
- 「LINE Bot 與群組管理」改為每個用途一列，使用下拉選單切換查看測試群／正式群，不再同時展開八列。
- 獨立 LINE 投票測試器維持退場；既有正式案件、票數、具名票向、結果圖、回饋、Word 與結案紀錄不變。

## 2026-08-28－v1.0.11 LINE 投票測試器退場

## 2026-08-28－v1.0.10 投票結果圖與副主席具名票向

- 進行中的正式案件與副主席專用結案資料頁新增「下載投票結果圖（PNG）」；形成通過或不通過決議後，可直接產生適合傳給三長群／董事顧問的統計圖。
- 結果圖顯示案件、申請者、專業別、截止時間、投票基數、最低參與、已投／未投、同意／不同意票數、比例、目前決議及產生時間；不列投票者姓名或逐人票向。

- App API 新增票數彙總及已投名單投影：一般會員委員只取得自己的選項，不能從前端或 API 取得其他人的同意／不同意；申請者迴避時不取得該案票數與票向。
- 共用投票領域新增 `voteSummary`／`voteCount` 彙總，首頁、案件中心、工作規劃、通知中心、月會與結案頁在委員資料被遮罩後仍顯示正確票數。
- 依 Sean 2026-08-28 決策，正式投票採記名保存，具名明細留在受權限保護的系統畫面；下載圖維持只呈現整體統計。

## 2026-08-28－v1.0.9 LINE 免登入投票與獨立測試器

- 記錄新會員、續約與轉換行業別的新版開票流程：副主席按「啟動投票流程」後，系統自動建立資格快照、無登入投票網址與可完整複製的正式公版，不再逐案建立 Google 表單。
- 副主席將公版原樣貼到會員委員會正式群；會員委員秘書Bot驗證一次性呼喚識別、文案指紋、案件快照及截止版本後，以該文字事件的 `replyToken` 免費回覆真正 @所有人通知與 Flex 投票圖卡。一般開票流程不再直接 Push。
- 第一版不綁定 LINE 帳號或要求 Supabase 登入；投票人從本案資格快照自行選擇姓名與同意／不同意，後端仍執行迴避、截止、每人每案一票及既有票不可自行修改等規則。
- Webhook只暫時解析命中的系統公版，不保存完整群組聊天內容；以呼喚識別、完整文案雜湊及原子狀態防止 Webhook 重送或同文重貼產生多張圖卡。
- 新增設定頁「LINE 投票測試器」：可選一位既有會員作為顯示對象，在測試群完成呼喚、Bot Reply、無登入選名與送票驗收；測試流程不建立正式案件、Word 或正式票，完成後可一鍵清除。
- 投票網址在 Bot 成功回覆圖卡後才開放收票；若 Reply 失敗，將同一份完整文案重新貼到相同群組即可重試，不會改用耗額度的 Push。
- 測試群與正式群可同時啟用，正式開票固定使用 `production` 路由，測試器固定使用 `test` 路由，互不覆蓋。
- 案件與測試資料刪除改為先建立附件清理工作；即使 Storage 暫時刪檔失敗也不再靜默忽略，系統會顯示警告並保留可追查、可重試的清理紀錄。
