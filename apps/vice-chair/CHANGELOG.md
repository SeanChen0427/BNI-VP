# 變更紀錄

## 2026-07-30－終期輔導 Word 動態答案缺漏修復

- 修正終期輔導已載入草稿後，正式 PALMS 會員資料再次建立第 3～10 題，導致畫面上已填答案被清空、Word 輸出成「未填寫」。
- 正式會員資料載入前先保存整份畫面狀態，動態題目建立後完整回填答案、選項與確認內容，再顯示正式表單。
- 產生 Word 前新增完整性檢查：第 3～19 題文字、效益／培訓選項、滿意度、MSP 與權責確認、訪談總結及意見未完成時一律停止產檔並定位到第一個缺漏欄位。
- 新增終期輔導答案保留順序與 Word 完整性回歸測試；不回寫、不覆蓋既有案件草稿或已保存 Word。

## 2026-07-27－案件身份鎖定與重複完成修復

- 既有排程的案件類型與會員姓名改為不可編輯；終期、期中、轉行業別、特定關懷與離會只能選擇正式會員，新會員申請仍可輸入申請者姓名。
- 月會關懷排定改為同時核對任務 ID、會員與案件類型；錯誤或過期連結會重新尋找正確任務，不再把甲會員的工作開成乙會員。
- 決議流程的案件類型、申請者與專業別固定由正式任務帶入；舊草稿與前端送出的內容均不得覆蓋正式案件身份。
- 五種訪談表在正式任務 ID、類型與會員核對完成前保持隱藏；資料不完整時停止操作，不顯示可能錯配的表單。
- 已完成案件再次送出改為冪等成功；同一委員因慢速網路或重複點擊再次完成時，不再因舊 revision 誤報「尚未完成案件保存」。
- 新增資料庫 trigger，禁止既有工作沿用同一案件編號改成另一位會員或案件類型；migration 僅新增未來寫入保護，未更新既有資料。

## 2026-07-27－訪談表單案件會員綁定修正

- 修正期中輔導表的基本初始化與正式案件帶入同時執行，造成首頁點選洪孟新案件後，較慢完成的預設資料又把會員姓名覆蓋成紀韻霓；主責與陪訪未被覆蓋，因此畫面曾出現不同案件資料混合。
- 終期、期中、新會員、轉換行業別與離會五種訪談表統一改為「基本表單完成後才帶入正式案件」，會員、日期、主責及陪訪不再互相競速覆寫。
- 案件連結同時核對 ID 與類型；找不到指定案件或正式會員時停止顯示表單，不再靜默改用名單第一位會員。
- 已存在的錯誤草稿會依案件 ID 自動校正會員、日期與指派資料並同步回 Supabase；只修正既有草稿，不會因單純開啟空白案件而建立草稿。
- 新增五種表單初始化順序、案件類型與錯誤阻擋的回歸測試。

## 2026-07-27－月會排定與案件資料一致性修復

- 修正 7 月舊版月會草稿可保留「已排定」與案件編號，但對應工作仍只存在舊瀏覽器、未搬入 Supabase，導致月會顯示邱德晏由紀韻霓追蹤，進行中案件卻為空。
- 月會保存改由 Edge Function 先核對 Supabase 任務；具備會員、案件類型、負責委員及日期的關懷排定若缺少案件，會先補建或連回既有案件，成功後才保存月會。
- 副主席／Admin 載入月會時會自動修復尚未結案的舊草稿並刷新任務快取；前台只有在 Supabase 真的存在對應案件時才保留「已排定」，避免再次產生假狀態。
- 修正任務交易 RPC 首次實際新增時，回傳欄位 `task_id` 與衝突目標同名造成的 PostgreSQL 歧義；改用明確主鍵 constraint，確保首筆與後續任務都能交易式寫入。
- 修正更新既有任務時，`due_at`、`completed_at`、`task_status` 等區域變數與資料表欄位同名造成的 PostgreSQL 歧義；交易函式的區域變數統一加上 `v_` 前綴，並完整限定 `RETURNING` 欄位。
- 新增月會／案件一致性回歸測試。

## 2026-07-27－每週點名更正與 LINE 預覽可用性

- LINE 公告預覽取消隨頁黏著與內框高度截斷，改為完整呈現且可選取文字；複製按鈕加入剪貼簿權限受限時的備援方式。

- 新增重複函式宣告防回歸檢查，避免後續部署再次造成整支案件 API 無法啟動。

## 2026-07-25－案件交易完整性與跨裝置復原

- 開票、投票、回饋、結案、重設與刪除案件改由 Supabase 交易 RPC 執行；正式案件、任務狀態、資格快照、票、回饋鎖定及稽核事件不再出現只完成一半的狀態。
- 既有 `task_case_states.workflow.votes` 依歷史資格快照補入正式 `votes`，並保留 `LEGACY_MIGRATION` 註記，避免畫面票數與正式資料庫統計不同。
- 訪談表偵測另一個裝置的新版本時停止自動覆寫，保留目前畫面並要求人工載入最新版本；revision 衝突不再被背景輪詢悄悄吃掉。
- 暫時斷線造成的任務／案件保存失敗會在回到頁面、重新取得焦點或 30 秒輪詢時自動重試；真正的 409 並行衝突仍停止重試並要求重新載入。
- 台灣日期判定統一使用 `Asia/Taipei`，避免凌晨 00:00–07:59 誤用 UTC 前一天而選錯任期、投票名單或離會日期。
- 登入頁不再顯示前一位使用者快取的委員名單；逾時重新登入可正確返回月會、分析審閱與常用連結頁。
- 新增交易 RPC、舊票補遷移、共同編輯防覆寫及斷線重試的回歸檢查。

## 2026-07-25－多人登入、回饋與投票並行安全化

- Supabase Auth 登出改為 `scope=local`；任何一台電腦登出或首次登入選擇委員姓名時，不再撤銷共用帳號其他裝置的 refresh token。
- 同一分頁的並行 API 請求共用單一 token refresh；登出中的 refresh 不得重新建立工作階段。
- 前後端登入名單都同時檢查人員啟用狀態、任期起訖與當期角色，不再只看 `status = active`。
- 委員回饋改存正式 `case_feedback`，以案件＋本人唯一；多人同時提交只更新各自資料列，不再共用整案 revision。
- 投票改存 `vote_snapshots`、`vote_snapshot_voters` 與 `votes`；開票由後端建立當期資格快照並強制申請者迴避，截止後停止投票，既有票不得由一般使用者改寫。
- 正式回饋、資格快照、票與案件事件撤銷前端直接權限，只能由 `app-api` 依 JWT、角色及登入後所選姓名操作。
- 排程與案件狀態在頁面重新取得焦點、回到前景及每 30 秒安全更新；本機正在編輯或同步失敗時不以遠端資料覆蓋。
- 新增兩位委員同時提交回饋與投票、單機登出及並行 refresh 的回歸測試。

- 所有主要任務／草稿／Word 操作改為等待 Supabase 確認後才顯示成功；失敗時保留本機資料並顯示固定警示。
