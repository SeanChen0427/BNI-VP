# 富聯分會新任副主席實務交接手冊

> 本篇保留作工作摘要。供新任自行學習的完整整合版請讀 [副主席完整工作指南](vice-chair-complete-guide.md)，含原課程心得、完整 321A、GROW 與後續處理；來源差異見 [整合對照](handover-integration-review.md)。

整理日期：2026-09-09。適用：新任副主席及交接帶領人。

本手冊依 已確認的職務作法、現行主題規格及系統操作內容整理。2026-09-09 新確認事項包括每週／月工作節奏、會員衝突調解、專業別協調、三長溝通與代理主席分工。未另確認固定季度例行工作，不自行增加。

本教材供每次換屆接續使用，以職務及用途描述工作；實際姓名、專業別、任期目標與數據由當屆更新。參考稿可自行改寫，歷史來源與決策另存於 [決策紀錄](decision-log.md)。

閱讀順序：先看 [工作心智圖](vice-chair-work-map.md)，再依本手冊完成第一次每週與月度作業，最後使用 [交接清單與上手驗收](vice-chair-handover-checklist.md)。

## 1. 接手後，你每天要能回答的問題

副主席負責讓會員委員會的工作持續有人處理、資料正確、程序完整，並與三長保持資訊與想法的交流。

打開工作總覽時，先回答：

1. 哪些事情有期限，哪一件需要先處理？
2. 每一件目前由誰負責，卡在哪一步？
3. 上次聯繫得到什麼回覆，下一步何時完成？
4. 是還沒做、已做待回覆，還是已完成但尚未留存證明？
5. 有哪些資訊需要和主席、秘書財務、董事顧問或相關職長交流？

基本工作循環：確認資料 → 指派 → 執行／聯繫 → 更新紀錄 → 檢查結果 → 接續追蹤或結案。不要只問「做了沒」，要確認下一步和完成證據。

### 來源怎麼看

- **富聯內規／現行決策**：分會已確認的實際做法。
- **中心區規範／表單原文**：以對應主題文件保存的來源與版本為準；正式核准仍依中心區。
- **系統操作**：現有產品的入口與行為，不能代替制度核准。
- **交接建議**：本手冊提出的紀錄、文案示例與演練方式，不是新增制度門檻。
- **歷任副主席參考文字稿**：每週報告、過往宣導、宣誓／畢業、封閉交接及 BOD 留檔僅供新任參考，可自行調整語氣、順序與內容，不要求照念；另有來源的正式內容及 PPT 公版／固定架構分開看。

## 2. 第一日：取得可以工作的入口

1. 開啟 [富聯工作台](https://seanchen0427.github.io/BNI-VP/)，使用副主席角色帳號並選擇本人姓名。
2. 確認任期與身份正確。Admin 負責設定換屆；新任副主席接手日常工作，不以 Admin 身份代替日常登入。
3. 看完全站導覽；進入需要使用的頁面時，再看該頁「操作教學」。隨時可以重看。
4. 確認 BNI Connect、正式寄件信箱、Zoom、常用文件及群組的實際使用方式與窗口。
5. 開啟工作總覽，盤點進行中案件、逾期工作、換屆待指派及續約地基。
6. 找一件交接中的工作，指出原主責、現在狀態、最後回覆、期限與接手人。

密碼與個人 API Key 透過私密管道交接或重新設定，不填入本手冊。正式會員資料及附件依系統權限查閱；教學範例使用去識別化內容。

## 3. 工作節奏：照這個順序循環

來源：富聯內規／2026-09-09 交接確認；詳細既有分工見 [每週出席流程](workflows.md#每週例會結束後發布出席紀錄)、[月會](monthly-committee-meeting.md)、[例會發言稿](meeting-scripts.md)。

| 時點 | 主要工作 | 本次要留下的結果 |
|---|---|---|
| 每週例會前 | 確認點名分工、代理資訊、報告與宣誓／畢業安排 | 當週分工及已確認名單 |
| 每週例會中 | 點名與出席核對、副主席介紹及報告，依安排主持宣誓／畢業 | 當日紀錄與完成環節 |
| 每週例會後 | 核對並發出席紀錄至公告群、完成相關 Connect 登錄 | 正確公告、發布時間及登錄狀態 |
| 每週持續 | 追蹤目前所有關懷及訪談進度，處理需跟進地基與待辦 | 主責、最新回覆、下一步及日期 |
| 每月第一週 | 會員委員會月會 | 會議紀錄、分工與追蹤日期 |
| 每月第二週 | 月度領導團隊報告 | 依固定 PPT 向全體會員說明 Power of One 目標及會員委員會的可執行方案 |
| 每月其餘時間 | 落實月會分工，繼續每週案件追蹤 | 決議有人執行，卡點持續處理 |
| 個別約定到期 | 依會員各項續約地基的週期核對 | 每期結果、證據與後續安排 |

第一週月會依既有安排在當月第一場實際舉行的例會後召開，遇假日按分會公告調整。第二週領導團隊報告通常提前在核心會前會確認 Power of One 目標，使用固定 PPT 架構向全體會員報告。固定架構的原檔或頁面內容尚待取得，不自行改成自由格式。

沒有另行新增「每季必須開一次會」或「每季必須產出報表」。個案若約定每三個月工作坊，依該會員地基起算日逐期追蹤，不直接套用曆季。

## 4. 每週點名、例會與公告

### 4.1 會前準備

1. 確認本週例會是否照常、日期及會議資訊。
2. 確認當週負責點名及儀容觀察的 1–2 位委員。
3. 核對現任會員及尚未進入月度主檔的過渡點名會員，避免新入會漏列。
4. 看來賓接龍群的代理登記；這只是預先資訊，當天仍需核對是否出席。
5. 準備副主席介紹與報告，將姓名、專業別、期間及數字換成當期已核對內容。
6. 在八長會前會說明關懷、規範宣導、新申請、下週宣誓／畢業、續約及委員燈號等事項。

本屆八長會前會曾安排週五 08:30，換屆須由當屆八長重新確認，不能把舊任時間當永久制度。

### 4.2 當日核對

1. 負責委員於 06:30、07:00 核對 Zoom 與會者列表。
2. 記錄出席、遲到／早退、代理及缺席；代理需確認實際上線。
3. Zoom 聊天的簽到／簽退供核對，不取代委員實際點名。
4. 名牌、PIN 章、服裝、開啟畫面是商務環境觀察，不直接轉成缺席、扣分或續約負面條件。
5. 會員簡報採當期設定；目前富聯為 25 秒。第一輪未講到者由主席在最後確認，最後仍未完成者依現行出席規則處理。
6. 紀錄有差異時，以當週負責委員紀錄為主要依據；有異議則由會員委員會協調並保存核對脈絡。

### 4.3 每週例會副主席環節報告

來源：2026-09-09 整理的現行文字稿；來源文字稿、整理者的編輯示例及歷史宣導表達範例見 [例會發言稿](meeting-scripts.md)。

這是每週面向全體會員的副主席報告，有可修改的公版 PPT。第二週 Power of One 月度領導團隊報告另有固定 PPT 架構，兩者分開準備。

歷任文稿的安排如下，供理解過往的報告方式；新任可自行組織段落，不要求照此順序：

1. 感謝主席、自我介紹。
2. 本屆分會人數與綠燈目標。
3. 半年來賓、商務交流、引薦單數、引薦金額及創會累計成果，感謝夥伴。
4. 會員委員報告，請全體查看上週出缺席畫面。
5. 分會地基與商務環境提醒：06:30 前出席、簽到退、正裝、名牌、PIN 章及鏡頭。
6. 續約提醒：紅燈有條件續約、灰燈不續約，到期日前兩個月的 15 日完成申請及繳費。
7. 等待商訪的新會員進度。
8. 當期需要徵求的行業，邀請夥伴協助咖啡會議。
9. 把主持棒交還主席。

**每月更新：**核對來源與統計期間後，同步更新文字稿及 PPT 數據。本次留檔的 51 人目標、半年來賓 80 人、交流 2,997 次、引薦 2,028 單、半年金額 3,800 多萬元、創會累計 2.5 億元、待商訪 1 位及徵求 8 個行業，都是本次稿件內容，不是永久數值，也不是本次重新計算的正式快照。目標依當屆確認，其他數據使用時核對期間。

**每週上台前檢核建議：**看文字稿與公版 PPT 是否一致，上週出席畫面日期是否正確，商訪進度及徵求名單是否有變動。待商訪為零時調整句子；不要念出尚未填寫的占位欄位。

**不定期宣導：**依核心團隊當次討論，確認哪些議題重要、需要提醒全體會員，再核對作法並撰寫當次宣導，配合 PPT 呈現。議題與篇數依實際需要，不是從三則舊稿中挑選。

交接提供的下列內容只供學習過往的語氣與表達方式，不作待選議題清單：

- 內部／外部引薦觀念，已提供的文案解說本人與夥伴合作的內部引薦。
- 代理人事先在來賓接龍群填姓名與電話，以利當天聯繫協助。
- 引薦僅登錄會員目前登錄的專業別服務，斜槓／副業不直接列入；有疑問先問委員會。

完成標準：自己準備的報告內容與當月數據正確、當週畫面及進度已核對、核心討論需宣導的議題已有對應文案，使用公版 PPT 完成報告並交回主席。每週公版檔案尚待取得，取得後再補各頁填寫教學，不自創頁序。

公開續約提醒之外，有個別地基的會員仍須符合系統所記錄條件；商務環境提醒的正式判定界線依本手冊 4.2 及工作流程。

### 4.4 宣誓與畢業

- 新會員與續約宣誓名單先經會員委員會確認，再於會前會提出。
- 秘書財務把環節加入例會 PPT，來賓接待組準備 Zoom 聚焦；副主席帶領宣誓。
- 畢業名單由導師協調員提出，副主席確認安排並主持。
- 使用 [例會發言稿](meeting-scripts.md)，副主席介紹保留中心區職責重點；當月數字放在報告段落。
- 三份供新任了解歷任主持表達方式的 [例會主持參考稿](meeting-ceremony-templates.md) 已去除舊個案姓名及數據；當週填入實際名單、專業別、引薦人、導師及核對後資料。
- 過往續約稿包含舉手、貢獻介紹、宣誓及說姓名、合照；新會員稿另有專業介紹、感想及引薦人／導師合照；畢業稿曾採逐位祝賀、感謝導師、先拍照再分享。這些是歷史安排參考，新任依當次議程自行調整主持順序與銜接。
- 試讀時核對同一人物從介紹到合照都用同一姓名、各人導師沒有串錯，未填欄位及未使用段落先清除。
- 正式誓詞按當次確認 PPT／文字宣讀，不由主持銜接稿自行補寫；副主席須等開麥、逐點回應、分享及合照完成，再交回主席。

### 4.5 會後公告與資料登錄

1. 核對當週日期、人數、名單及六個月累計期間。對缺資料或期間錯誤先查明，不能用 0 補上。
2. 從文稿範本準備「每週出席紀錄公告」，再核對姓名與數字。
3. 發到富聯 LINE 公告群；公告不包含會員電話或訪談私密內容。
4. 留存發布時間。產生或複製文案不等於已發布。
5. 依既有分工在 BNI Connect 登錄當週出缺席、檢查會員填報異常，並依核心群執行秘書提供的培訓簽到表登錄培訓積分。
6. 點名頁不是 PALMS 正式統計替代品；後續分析以 Connect 匯出並核對的 PALMS 為準。
7. 參加八長會後會，復盤例會、確認來賓簽單與後續追蹤人；需要咖啡會議時記錄接手者及下一步。

完成標準：公告實際發布，資料登錄完成或待補原因清楚，後續工作有負責人。

## 5. 每週把所有關懷與訪談追到下一步

來源：[任務管理](task-management.md)、[案件流程](workflows.md)、2026-09-09 交接確認每週追蹤全部進度。

1. 開啟工作總覽及會員案件，掃過所有未結案件；不要只看自己負責的案件。
2. 每案核對主責、陪訪、期限、目前階段、最後聯繫及下一步。
3. 未指派者先指派；已指派但未約時間者追排程；已訪談者追表單與 Word；需投票者追回饋及投票；通過者追確認與送件。
4. 主要負責人只有一位，陪訪 0–2 位；陪訪可補紀錄，整體任務由主責勾選完成。新會員標準商訪安排另依新會員流程。
5. 會員未回覆時，記錄聯繫時間、管道及未回覆，排下次追蹤；沒有統一規定的催辦間隔，不自訂為分會制度。
6. 卡在跨職務協作時，和相關窗口及三長交流，明確留下誰處理哪一項。
7. 結案前確認適用的文件與審核完成，不能用「有訪談」取代「已保存」或「已核准」。

催辦文案示例（可自行改寫）：

> 【案件／會員代稱】目前在【階段】，想確認【待完成事項】的進度。請協助回覆最新狀況、是否需要支援，以及預計下一步完成日期，我會同步更新紀錄。

## 6. 第一週：會員委員會月會

來源：[月會規格](monthly-committee-meeting.md)、[續約地基](renewal-foundation-tracking.md)。

### 6.1 會前

1. 確認實際月會日期與當期會員委員名單。
2. 從 Connect 匯出上一完整月份 PALMS，透過首頁「每月資料更新」依畫面所列類別及期間上傳。
3. 核對目前正式月份與預備月份，不把預備資料當成已切換的正式資料。
4. 確認月會出席摘要使用上月單月 PALMS；會員關懷及燈號按其正式分析期間，不能把半年統計當單月。
5. 檢查來源、期間、讀取時間及缺資料提示。有缺漏先補，讀取失敗不能講成「沒有人需要關懷」。
6. 預讀續約、紅燈／需輔導、期中關懷、進行中案件及地基摘要。

### 6.2 按五個議程帶會議

| 議程 | 要說明／討論什麼 | 要留下什麼 |
|---|---|---|
| 上月出席狀況 | 會員數、缺席、遲到／早退、代理總次數及涉及會員 | 正確月份與核對後摘要 |
| 分會成長與留員 | 分會規模、申請、流失、審查及續約概況 | 實際狀況與需要協作的問題 |
| 續約及需輔導會員 | 討論續約、關懷、現有案件與地基 | 是否追蹤、主責、陪訪、日期及備註 |
| 會員協助事項 | 「目前是否有聽到任何會員有需要協助的地方呢？」 | 需求與下一步 |
| 臨時動議 | 委員提出的其他議題 | 討論結果；建議補記執行人及期限 |

分會人數目標使用當屆確認值，舊任曾設 51 人，不自動當成新任目標。統計口徑仍待確認的項目，核對來源再說明，不自行創造算式。

### 6.3 會後落實

1. 需要後續工作的項目填妥追蹤委員與日期，依畫面選填陪訪。
2. 若會議確定本次不安排關懷，使用適用的「不安排關懷」決議並建議記錄原因；不為了結案建立假任務。
3. 續約項目的「確認不續約」需依實際已確認決議使用，不由燈號自行推定。
4. 不安排工作不會自動取消已有案件，也不代表修改會員資格；既有工作另行檢查。
5. 確認需要建立／更新的工作已同步到工作總覽；同步失敗時先處理錯誤。
6. 核對後完成月會結案，下載 Word，重新開啟確認內容與日期。正式月會紀錄保留當次快照。

完成標準：議程有紀錄，需執行的決議有人及日期，適用的免排程決議已記錄，月會正式保存且 Word 可閱讀。

## 7. 第二週：月度領導團隊報告

**已確認安排：**每月第二週進行月度領導團隊報告。依 2026-09-09 交接補充，通常提前在核心會前會確認一個 Power of One；在本項工作的語境中，就是設定一個目標，提出會員委員會如何協助達成的可執行方案，依固定 PPT 架構報告給全體會員知道。

### 7.1 核心會前會：先確認目標

1. 在報告前的核心會前會，與核心團隊確認本次 Power of One 目標。
2. 釐清本次希望達成什麼，以及會員委員會可以協助的部分；不是由副主席自行選定目標後才告知其他人。
3. 第一週會員委員會月會的討論、關懷與訪談進度可作為方案準備素材，但月度報告的主軸是已確認的目標與可執行方案。

### 7.2 把目標寫成可以執行的方案

依目標提出會員委員會實際會採取的行動。以下是交接用方案檢核建議，不代表固定 PPT 的頁面名稱或既定欄位：

- 要做哪幾個具體動作，如何幫助本次目標。
- 誰負責、何時執行，需要哪些角色或會員配合。
- 如何追蹤執行情況，以及用什麼結果確認進展。

避免只有「加強關懷」「提升參與」等方向而沒有下一步。方案細節在準備時與相關人員協調，不把尚未確認的安排當成已承諾事項。

### 7.3 套用固定 PPT，向全體會員報告

1. 取得既有月度領導團隊報告 PPT，沿用固定架構及順序。
2. 把已確認的 Power of One 目標與會員委員會方案填入對應位置。
3. 核對內容與核心會前會共識一致；使用數據時核對期間及來源。
4. 第二週依例會／當次安排，向全體會員說明目標、會員委員會會做什麼，以及需要會員如何配合。
5. 報告後依方案執行並納入每週追蹤，留下進度與需要調整的事項。

完成標準：目標已在核心會前會確認，方案能實際執行，PPT 沿用既有架構，已向全體會員報告，後續行動有人接續追蹤。

**教材待補：**固定 PPT 原檔或頁面內容尚未在目前專案查得，取得後才能補上逐頁填寫教學；不自行編造頁數、頁名或替代模板。這不影響上述工作定位與流程已確認。

向全體會員報告使用必要摘要，不放完整訪談或健康、家庭等敏感細節。詳細來源見 [月度領導團隊報告](monthly-leadership-report.md)。

## 8. 五種訪談：先辨識類型，再照程序走

來源：[案件完整流程](workflows.md)、[表單對應](forms/interview-forms.md)。

| 案件 | 使用表單 | 回饋／投票／董顧確認 | 特別注意 |
|---|---|---|---|
| 新會員 | 新會員訪談／高屏區會員訪談表 | 需要 | 先確認申請、繳費及專業邊界 |
| 續約／終期輔導 | 終期輔導表 | 需要 | 準備指定年度資料、燈號及既有地基 |
| 轉換行業別 | 高屏區會員訪談表－轉換行業別 | 需要 | 確認新服務範圍及與既有會員關係 |
| 期中輔導／關懷 | GROW 期中輔導表 | 不需要 | 完成表單並成功保存 Word 後結案 |
| 離會訪談 | 離會訪談表 | 不需要 | 可選擇補訪；與離會登記獨立 |

### 表單與附件共通操作

1. 從正確案件進入表單，先核對會員與案件類型。
2. 主訪整理紀錄，陪訪補充觀察；不要把推測寫成會員承諾。
3. 確認必填及必要附件，產出並成功保存 Word。
4. 檢查 Word 可重新下載、內容和會員正確。只保存草稿或只拿到本機檔案，不等於案件附件已成功保存。
5. 依案件類型進入下一階段；期中與離會不額外開投票。
6. 已結案從「結案資料」重開查閱，保留歷史內容與證據。

## 9. 新會員：申請、專業確認、審核到入會

### 9.1 前置與安排

1. 秘書財務確認電子簽單與繳費，建立新會員協助群並提供申請 PDF。
2. 副主席核對資料、跟進申請者。來源流程要求 48 小時內跟進；精確起算點仍列待確認，接到案件便安排，不自行延後等待。
3. 安排主訪與協訪，標準新會員商訪依現有流程採 1 位主訪、1 位協訪、預留約兩小時並以線上為原則。
4. 使用新會員表單與富聯內部 321A 指引，確認經驗、經營、專業定位與合作態度。指引不是系統自動淘汰門檻。

### 9.2 專業別確認與利益衝突協調

來源：**富聯內規／2026-09-09 交接確認**，詳見 [專業別主題流程](workflows.md#專業類別界定與既有會員協調)。

1. 一個分會每個專業類別只設一位代表。訪談要問清楚實際服務內容、主要客群、案件類型與不承接範圍，不能只看「房仲」等寬泛名稱。
2. 找出與既有會員相近的服務，向既有會員說明有這位申請者及其實際專業。
3. 有疑慮時邀請既有會員共同討論，確認現在及未來是否有服務衝突。
4. 可劃分時，與雙方說明服務界線及未來合作方式，確認原會員與申請者都同意並承諾。
5. 建議把討論日期、參與人、界線、雙方確認及後續安排記入受控案件紀錄，避免交接後只剩口頭理解。
6. 無法消除衝突或未取得雙方同意時，以既有會員為主，不讓新會員加入，依未通過程序辦理退款及婉拒。
7. 專業界線達成共識後，仍須完成委員會回饋、投票、董事顧問確認及正式送件，不等於直接核准。

**教學案例 A：**既有會員服務北高雄住宅買賣；申請者雖稱房仲，訪談後確認主要做土地買賣。可辨識不同服務定位，仍向既有會員說明申請情況，不只在訪談人員之間自行判斷。

**教學案例 B：**申請者也做一般住宅。與既有會員及申請者討論是否存在利益衝突、未來如何合作與劃分；雙方同意並承諾後才繼續入會審核。

**教學案例 C：**兩人服務重疊且無法接受界線。優先保障既有會員，不因申請者已繳費便讓其加入，走未通過、通知與退款程序。

### 9.3 通過與未通過的後續

- 通過：完成適用的訪談會員確認、委員會及董顧確認，備齊資料送中心區；協調宣誓、會員包及 MSP 手冊，追蹤 Connect 建檔與開通信。
- 新會員在開通信後兩個月內完成 MSP（上）、MSP（下）各一次，與續約規則不同。
- 未通過：整理原因 → 董事顧問同意不予入會 → 副主席通知申請者及引薦人、秘書財務通知退款 → 中心區執行會計辦理 → 核對退款結果再結案。退款天數、費用與資料保存細節未確認者不自行承諾。

## 10. 續約：核對三個日期、必須符合的地基與後續作業

來源：[續約流程](workflows.md#續約會員流程)、[續約審核](policies/renewal-review.md)。

| 時間 | 要做什麼 | 來源 |
|---|---|---|
| 到期前 4 個月 | 和秘書財務核對名單、開始續約作業 | 中心區規範 |
| 到期日往前兩個月的 15 日 | 完成續約申請及繳費的主要行動截止 | 富聯內規 |
| 到期前 30 日 | 完成全部續約作業 | 中心區規範 |
| 續約完成公告後 8 週內 | 追蹤 MSP（上）或 MSP（下）任一堂 | 現行確認規則 |

例如 9/1 到期，富聯申請繳費截止為 7/15。不要把中心區最後期限當成日常才開始催辦的時間。

### 續約地基是必須核對的條件

來源：富聯內規／2026-09-09 交接確認。會員如有已約定的續約地基，必須符合該地基；續約審核須逐項核對，不能只確認繳費、訪談或燈號而略過地基。

系統已保存會員的地基條件、適用期間、完成進度及相關紀錄，並提供追蹤提醒。副主席應從「續約地基追蹤」查看原有約定及結果，再帶入本次續約訪談與審核：

1. 查看該會員所有適用地基，核對指標、目標、起訖日期、逐期或累計要求。
2. 檢查各期完成紀錄與證據，區分已符合、尚未符合、資料待補及尚待人工確認。
3. 查看系統提醒與過往聯繫紀錄，向主責確認仍待完成或補證的部分，持續追蹤至可核實。
4. 將逐項核對結果寫入訪談及審核資料。未符合的條件不能省略或直接標成已符合；資料待補時先補齊，不逕判已達標或未達標。
5. 依實際結果完成委員會、董事顧問與中心區適用程序；系統紀錄及提醒不等於自動核准或自動拒絕續約。

無既有地基者不自行增加條件；有地基者按原約定核對，不因換屆、訪談結案或付款而免除。

### 完整續約作業

1. 核對申請、款項及名單，安排主訪與陪訪。
2. 依富聯截止日前最後完整月為結算月，準備往前 12 個完整月份資料及結算月燈號；不直接拿任意最新期間代替。
3. 完成終期輔導；有續約地基者必須逐項核對是否符合，帶入系統保存的條件、各期完成證據、提醒與追蹤紀錄，不只顯示摘要。
4. 依案件流程完成回饋、投票、會員訪談確認、三長群資料包及董顧確認。
5. 核對中心區送件與最終回覆，記錄公告及後續 MSP 追蹤。
6. 有條件續約以委員會個案討論、董顧確認的條件為準；燈號、AI 建議或數字達標不自行代替資格判斷。
7. 訪談結案後，尚未到期的地基繼續追蹤。

## 11. 回饋、投票、確認與結案

來源：[投票規則](voting-rules.md)、[商訪子流程](workflows.md#續約新會員轉換行業別商訪回饋與投票子流程)。

1. 先核對案件類型、當期資格與訪談 Word。
2. 主訪及陪訪先表述，委員閱讀後回饋。回饋人數超過投票基數一半後才開投票；回饋與投票是不同狀態。
3. 投票基數為當期副主席 1 位加有效會員委員；最低參與人數為 `floor(基數 / 2) + 1`。
4. 達到參與門檻後，贊成與反對採多數決。同票不形成決議；例如基數 7、投 4 票且 2:2，仍需等下一票。
5. 主訪、陪訪仍要回饋並保有投票權；申請者本人同時是副主席／委員時才依既有規則迴避。額外迴避與特殊情形不自行改資格快照。
6. 使用系統產生的投票網址及完整呼喚公版，核對指定群組後原樣貼出；須確認 Bot 回覆成功後投票開放。複製不等於 LINE 已送達。
7. 截止或文案版本改變後，重新產生並貼送新版，舊網址不再沿用。
8. 依正式票數核對結果，不用群組「已投」留言替代票數。
9. 取得會員對訪談內容的確認；敏感確認資料只按必要權限保存及送件。
10. 送三長群資料包含文案、投票結果圖及完整訪談單張直向長圖；續約另附一年培訓及來賓資料。
11. 保存董顧同意及中心區適用收件／回覆證據。投票通過不等於中心區最終核准。
12. 副主席在適用階段完成結案，從結案資料重新下載 Word 並檢查歷程。

截止時仍平票、棄權、額外利益衝突等尚未確認細節，保留紀錄並與相關窗口確認，不擅自宣布結果。

## 12. 地基、當責信與資料審閱

### 12.1 續約地基

依 [續約地基追蹤](renewal-foundation-tracking.md) 操作：

1. 每週看需跟進會員，展開其每項條件及各期結果。
2. 核對指標、目標、起算日、含當日的結束日及追蹤人；同會員不同地基各自判讀。
3. 來賓／培訓看正式資料的期間及證據；資料待補不等於未達成或 0。
4. 工作坊由副主席依實際參加日、場次與證據逐期確認，PALMS 培訓積分不能代替指定工作坊證明。
5. 週期超額不抵下一期；舊期未完成也不因新期開始就消失。
6. 實際聯繫後記錄管道、日期及回覆；複製提醒文案不算已聯繫。
7. 改期需記錄原因並重新核對受影響期間；舊確認不一定適用新期間。
8. 錯誤項目可依系統刪除／復原並留痕，不用刪除來掩蓋未完成。
9. 換屆後保留原條件及歷程，完成待改派。追蹤結果不自動變更會員資格。

### 12.2 當責信

依 [當責信流程](accountability-email-workflow.md)：開啟待寄任務 → 核對期間、次數、收件及副本、公版 → 補齊資料 → 複製到正式信箱並人工寄出 → 回工作台標記已寄送及時間 → 視回覆安排關懷。

不把「產生草稿」「已複製」「通知已讀」當成寄信完成。文字或資料待確認時先補齊，不自行創造門檻或處置內容。

### 12.3 月度分析與 AI

核對每月資料更新狀態及正式分析期間；若使用月度 AI 審閱，以新任副主席自己的 Key 設定，審查文字、來源與個案脈絡後才發佈。AI 解讀不能重算 BNI 分數、替委員投票或核准資格。

不把上傳成功直接當成分析已完成、已審閱或已發佈；各階段核對畫面結果。有缺報表、會員對帳失敗或資料錯誤時，記下訊息並交由系統維護窗口查明，不人工改分數湊結果。

## 13. 會員衝突、三長溝通與代理主持

來源：富聯內規／2026-09-09 交接確認。

### 13.1 會員之間的衝突

會員委員會的角色是調解及關心，不對會員間爭議給予裁決。

建議執行方式：先了解各方需求與描述 → 協調可討論的時間和問題 → 協助雙方提出可接受的下一步 → 記錄共識或尚無共識 → 依需要繼續關懷。紀錄區分各方說法與共同確認，不寫成委員會判定誰對誰錯。

「未達共識」可以如實留存，不強行填成調解成功。若另涉及正式入會、續約或資格程序，回到相應制度處理；調解結果不能自行替代該程序。

### 13.2 三長之間的日常交流

沒有一份固定的「哪些資訊只能回報主席、哪些只能回報董顧」日常清單。三長需要同心，平時主動分享資訊、觀察、想法與需要協作的事情。

交流時可用四句話：現在發生什麼 → 我目前怎麼理解 → 已經做了什麼 → 想一起討論／需要協助什麼。

此原則不取消新會員、續約、轉換行業別等正式案件既有的董顧確認與中心區程序；日常溝通與正式核准證據各自完成。

### 13.3 代理主席主持

主席需要副主席代理時，由主席提供文字稿與相關細節，確保例會正常運作。副主席不必自行設計一套主席議程。

建議代理前核對：當次議程及版本、逐字稿、PPT、環節交接與主持人、特殊宣布、Zoom 配合人員、疑問聯絡方式。先通讀並把不清楚的地方問清楚，當天依主席提供的安排執行，會後回覆完成狀況與需改善處。

## 14. 離會與其他偶發需求

- **BOD 講解**：依當次安排自行準備，可參考 [BOD 參考文字稿](bod-speaking-template.md)，先核對姓名、統計期間、交流與交易成果、生態圈及完整產業鏈，再準備互動；保留鼓勵合作的語氣，舊稿數字不直接沿用。不另設定固定週期，也不併入每週或月度 Power of One 報告。

- **離會登記**：使用設定頁既有離會登記入口，核對本人、日期及實際處理依據，依系統保存。不要分別人工刪改不同名單。
- **離會訪談**：與離會登記獨立，已離會者可補訪；不因補訪把會員恢復為在籍。完成表單及 Word 即按該類型結案，不追加投票／董顧／公告流程。
- **會員資格證需求**：依 [資格證流程](workflows.md#會員資格證申請流程) 核對適用版本與條件、必要佐證、主席／董顧意見及中心區結果；新任副主席不能自行承諾一定核發。
- **資料或按鈕異常**：先核對身份、案件階段、日期及是否有讀取／保存失敗提示；記錄可重現步驟交維護窗口，不重複發送或建立重複案件。

## 15. 換屆：移交正在進行的責任

1. 舊任與新任共同盤點所有未結案件、地基、待寄信、待中心區回覆、退款、宣誓、MSP 追蹤及承諾。
2. 每項留下原主責、最後進度、未完成原因、下一步、期限、接手人與資料位置。
3. Admin 預排下一屆完整名單與生效日；預排不立即切換現任權限。
4. 生效後確認新任副主席能以正確角色使用工作台，處理集中「換屆待指派」。同角色留任工作維持原指派，不重建案件。
5. 地基另檢查待改派與各期結果；舊約定不能因換屆重新起算。
6. 保留已結案資料及歷史投票、Word、主責與歷程，不為換屆刪除舊資料。
7. 逐群確認加入、用途、主管與必要管理權；三長原則上加入分會所有群組。其他職長群以掌握狀態為主，涉及職責或被詢問時介入。
8. 離任時依共用帳號制度更換共用密碼；個人 AI Key 重新設定，維運帳號與備份責任交由明確窗口。
9. 使用驗收表做去識別化演練；正式案件在實際授權與真實工作需要下操作，不拿來練習發送、投票或結案。

### 封閉交接中的副主席環節

來源：2026-09-09 整理的主持留檔及 PPT 保密承諾。可參考 [封閉交接參考文字稿](closed-handover-script.md) 了解過往安排；新任自行撰寫銜接，以下不是逐字或固定順序要求：

1. 新任副主席說明自己設定的任期目標；舊任四大專員分工、363 關懷與保留率 80% 只作歷史參考，不直接沿用為新任目標。
2. 介紹當屆會員委員，逐位念出姓名與專業別，核對名單完整。
3. 邀請所有會員委員開啟麥克風，說明這是委員會對分會的承諾與責任。
4. 切到「會員委員會保密承諾」PPT，共同宣讀已保存的原文，完成後依當次議程銜接。

這個保密承諾與新會員／續約會員宣誓詞分開；準備文稿不代表已完成實際宣讀。當屆個人資料只填在受控的工作稿。

## 16. 怎麼判斷交接成功

新任副主席可以自己找到資料、完成一輪每週工作、準備月會及領導團隊報告、辨識五類案件差異、處理專業邊界討論、追蹤未完成責任，並知道哪些仍需人工確認。

詳細勾選表與情境題見 [交接清單與上手驗收](vice-chair-handover-checklist.md)。這是本次整理的建議驗收標準，不宣稱新任已經完成演練。

仍需個案補齊的是實際接任者、當屆聯絡窗口、群組權限、未結案件清冊及實際驗收證據；既有制度未決細節見 [未決事項](OPEN_QUESTIONS.md)。這些實際資料應在受控位置填寫，不能把空白模板當成已完成交接。
