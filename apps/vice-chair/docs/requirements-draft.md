# 富聯會員委員會工作系統需求草案

狀態：需求蒐集中  
建立日期：2026-07-10

## 一、產品定位

本系統不是單純的紅綠燈分析工具或副主席學習平台，而是「富聯分會會員委員會工作系統」。副主席具備較高管理權限；新任副主席上手指南只是副主席權限下的交接與學習工具之一。

系統應讓接任副主席登入後，能立即掌握：

- 每月資料更新：首頁提供半年 PALMS、一年 PALMS、單月 PALMS與每週審計資料的副主席專用上傳區；每月自動換期並以實際檔案期間判定完成。
- 月度分析遇到「到期報告有、PALMS 無」的名單差異時，副主席可在分析頁逐人確認離會；確認後正式會員主檔立即更新並重新對帳，後續月份不再重複詢問。上線前即離會、未曾匯入主檔者建立歷史離會紀錄但不得進入現任名單；未確認者維持阻擋，不可被系統自動判為離會。
- 現在需要處理的工作。
- 哪些會員需要關懷。
- 哪些期限即將到來或已經逾期。
- 哪些案件與決議尚未完成。
- 每項工作應如何執行。
- 前任留下的必要脈絡與未結事項。

成功標準是讓職務不因人員交替而中斷，新任副主席不需要理解 Git、程式碼或本機開發環境即可接手。

### 技術與資料架構方向（2026-07-14）

- 現有 BNI 分析工具保留為計分與診斷的唯一來源，副主席系統以版本化分析快照整合，不重寫規則。
- GitHub Pages 只承載前端程式，不保存真實會員資料或敏感附件。
- 正式後端優先採 Supabase：Auth、PostgreSQL、Private Storage 與 Edge Functions 分別負責登入、結構化資料、文件附件及 LINE／AI 敏感操作。
- 完整架構、資料存放對照、GitHub 邊界及實作順序見 `docs/architecture-hosting-security.md`。

### 個人 AI API 設定（2026-07-16）

- 副主席與會員委員可各自綁定 OpenAI GPT、Google Gemini、Anthropic Claude API Key，三家可同時存在。
- 每位登入者使用自己的 token 額度，並可選擇預設回答平台；不得使用富聯共用 API Key。
- 設定頁提供三家官方申請教學、綁定狀態、末四碼、替換及移除功能。
- API Key 不得進入 GitHub、前端程式碼、localStorage、會員資料或操作紀錄；後端保存後不得再向前端回傳完整 Key。
- 本機原型以預覽伺服器在專案外加密保存；正式 SaaS 維持共用帳號（2026-07-19 決策），Key 依登入後所選姓名隔離並由後端加密儲存。此隔離屬信任機制而非嚴格身份驗證，Sean 知情接受。（原「必須配合一人一帳號」要求已被取代）
- 第一階段只完成 Key 綁定，不呼叫模型；第二階段再建立制度查詢對話框與知識庫檢索。
- AI 回答必須限於系統已有資料，顯示來源與版本；找不到資料時拒答，並固定提醒詳細規範仍須向中心區確認。
- AI 不得代替會員委員投票、決定續約／入會／轉換行業別或作成任何資格處置。
- 工作總覽提供右下角懸浮入口，可展開與收合對話框；同一登入工作階段內保留最近對話，避免每次重問。
- 後端先檢索白名單制度文件，只把相關摘錄送至選定 AI；查無相關資料時不得呼叫外部 AI。

## 二、使用角色

### 1. 副主席

- 查看與管理所有必要資料。
- 匯入及更新報表。
- 查看會員燈號、續約、審計與關懷結果。
- 建立、指派、追蹤及結案會員案件。
- 查看全部關懷紀錄與副主席專屬敏感備註。
- 管理會員委員帳號及工作分派。
- 管理工作流程、備份、資料匯出與職務交接。
- 將候任者移交為新任副主席，並撤銷卸任者權限。

### 2. 會員委員

- 查看執行工作所需的會員資料。
- 查看分派給自己的訪談、關懷或案件。
- 填寫聯繫紀錄與處理進度。
- 回報需要副主席決策或升級處理的事項。
- 查看與自己工作相關的會議安排及決議。
- 不可修改計分規則、原始報表、系統設定與帳號權限。
- 不可查看副主席專屬敏感備註。

### 回饋代填權限（2026-08-04）

- 副主席可依會員委員透過 LINE 提供的內容，選擇該名現任會員委員並代填案件回饋；會員委員不能替其他人填寫。
- 系統同時保存「回饋歸屬委員」與「實際操作副主席」，並在案件頁標示代填，不得把代填偽裝為委員本人操作。
- 副主席不得覆蓋會員委員本人已提交的回饋；會員委員可在之後以本人內容取代副主席代填內容。
- 申請者迴避規則照常適用；投票不開放代投。

### 中心區續約完成確認（2026-08-04）

- 只有副主席／Admin 可在月度分析審閱頁記錄中心區辦公室已完成續約；分會案件結案、投票、董事顧問同意或付款完成均不得自動觸發。
- 每筆確認綁定會員及當次官方原到期日，保存中心區完成日、確認者與確認時間；誤確認可撤銷並恢復提醒。
- 確認後只排除同一到期週期的續約雷達項目，不推算或改寫新到期日。官方到期報告更新日期後，自動進入下一週期。
- 已發佈分析快照不可回寫；確認後目前草稿會重新計算並清除舊 AI 審視，需重新審視與發佈新版本。

系統需另有帳號復原機制，避免唯一管理者失聯或帳號失效；此機制不是第三種日常使用角色。

## 三、副主席正式職責

依 2026-07-10 提供的「副主席的角色與職責」資料：

1. 分會專業別確認與紀律維持。
2. 確保會員委員會都能做好自己的角色、各司所職，及時予以改正回饋，並回報主席和董事顧問。
3. 維護 PALMS 表及分會紅綠燈。
4. 訪談新會員入會、舊會員續約申請及期中輔導。
5. 解決專業別爭議及其他會員衝突事件。
6. 寄發當責信給遲到及缺席會員。
7. 主席無法出席時，代理主席主持會議。

## 四、第一階段功能模組

### 1. 會員委員會首頁

- 首頁定位為「本月會員狀態與工作規劃儀表板」。
- 今日、本週與本月待辦。
- 即將到期或逾期事項。
- 優先關懷會員。
- 未完成訪談、未結案件與待回覆事項。
- 續約截止、行業別開放及出勤紀律提醒。
- 下次會議前需完成的準備。

首頁以行動與決策為主，不以全員排名或大量報表為主。

- 系統改版資訊不得加入案件提醒鈴鐺；鈴鐺只處理需要使用者採取行動的工作提醒。
- 首頁提供小型 `NEW・版本號` 入口，點開顯示發布日期、簡短更新摘要及資料影響說明；確認閱讀後移除 `NEW` 但保留版本號。
- 一般更新不自動打斷操作；只有標記為重要且目前登入身份尚未閱讀的版本，才在登入後主動顯示一次。
- 「系統與個人 AI」提供使用者版歷次更新，內容限 2–4 項功能或操作影響，不顯示程式、migration、commit 等技術細節。

左側主選單依日常工作分類，包含工作總覽、會員案件、訪談與輔導、投票與決議、出席與紀律、會員數據、常用資源、交接與學習及系統設定。新會員、期中、終期、轉換行業別及離會表單集中於「訪談與輔導」；當責信待寄、文稿範本與常用連結集中於可收合的「常用資源」。

### 2. 會員關懷中心

整合現有會員紅綠燈分析工具的能力：

- PALMS 報表匯入與名單對帳。
- 紅綠燈診斷。
- 黃燈升綠計畫。
- 行業別開放警示。
- 續約截止與續約審查預警。
- 新會員適應追蹤。
- 數據真實性審計。
- 個人關懷紀錄與後續追蹤。

現有計分規則仍由原專案管理；未經資料驗證與確認，不在本需求草案中變更。

副主席與會員委員的日常介面只提供「會員關懷儀表板」，不顯示完整 BNI 分析工具入口。完整分析工具保留獨立技術路由，僅供系統開發人員進行資料對帳、規則檢查與除錯。

會員委員會月會只帶入必須當場決定分工的續約、排除新會員後的紅燈／需輔導、期中關懷及既有關懷案件。新會員追蹤、審計觀察與結構性／其他線索不在月會重複呈現；需要細節時另開會員關懷儀表板。月會完成追蹤委員與日期後，須同步建立或更新工作台任務。

### 3. 專業別與席位管理

- 會員正式專業類別。
- 專業類別確認及異動紀錄。
- 相近或重疊專業類別提示。
- 專業類別爭議案件。
- 行業別開放狀態與處理紀錄。
- 決議、依據、負責人及後續期限。

### 4. 會員委員會管理

- 會員委員名單與工作分派。
- 每位委員負責的會員、訪談或案件。
- 工作完成情況與逾期提醒。
- 委員回報與副主席回饋。
- 需回報主席或董事顧問的事項。
- 會員委員會議與決議追蹤。

### 5. 訪談管理

訪談分為：

- 新會員入會訪談。
- 舊會員續約訪談。
- 會員期中輔導。

目前表單對應：

- `363 留員計畫－終期輔導`：續約訪談。
- `363 留員計畫－期中輔導（GROW）`：期中關懷。
- `高屏區會員訪談表`：新會員訪談及轉換行業別訪談。
- `離會訪談表`：離會訪談。

每次訪談至少記錄：

- 訪談類型、原因及期限。
- 負責人與參與人員。
- 標準問題或檢核表。
- 訪談摘要。
- 會員承諾或後續改善事項。
- 下次追蹤日期。

五種表單的主要完成操作統一為「完成訪談並產生 Word」。只有 Word、案件附件與流程狀態全部保存成功，才顯示持續的完成回饋；畫面須列出完成時間、檔名及「訪談已完成・待發送委員回饋」狀態，並提供前往回饋流程、返回案件中心與再次下載。清除操作只移除未完成草稿。
- 完成狀態及是否需升級回報。
- 使用的表單名稱、版本、原始檔與填寫完成版本。
- 主要負責人、陪訪人員及必要簽名／確認。

系統應將表單欄位數位化並保留原始文件版本，不可只上傳一個無法搜尋的檔案。PALMS、紅綠燈、會員姓名、專業類別及日期等已知資料應自動帶入，再由訪談人員確認。詳細欄位見 `docs/forms/interview-forms.md`。

### 6. 紀律與當責信

- 從 PALMS 辨識遲到、缺席、等效缺席與代理人次數。
- 顯示是否達到通知門檻。
- 依正式出席資料、通知類型與累計次數，產生對應的缺席或代理當責信草稿。
- 缺席第 2 次及第 3 次為觀察期通知；缺席第 4 次對應「開放行業別（專業類別）當責信」，現有公版內文包含會員資格正式終止文字。
- 代理另有獨立當責信；代理與缺席必須分開累計、分開顯示通知級別，不得共用次數或直接套用缺席公版。【富聯內規】滾動六個月累計第 6、7、8 次代理時，每一次都分別觸發副主席「代理當責信待寄」提醒；第 9 次對應「開放行業別（專業類別）當責信」。
- 第 6、7、8、9 次每封信的主旨與內文都必須明確顯示本次代理累計次數與滾動六個月計算期間。
- 由副主席確認後寄發，不直接自動寄送。
- 保存寄發日期、內容版本、操作者、會員回覆及後續關懷。
- 第 4 次缺席或第 9 次代理達門檻時，系統都立即產生開放行業別當責信待寄任務與可複製草稿，不設待核准狀態或核准關卡。副主席查看資料後自行複製至正式信箱寄送；系統不自動寄送或自動作成資格處置。
- 當責信公版原文與尚待確認的制度問題見 `docs/email-templates.md`。
- 當責信提醒、核對、預覽、複製、寄發留痕、防重複及驗收條件的完整功能規格見 `docs/accountability-email-workflow.md`。
- 第一版已實作副主席／Admin 專用待寄中心、首頁通知、Supabase 任務與事件稽核；系統只提供剪貼簿複製及人工寄送標記，不含自動寄信或核准流程。正式外部公版取得前使用有版本號的中性事實草稿。

### 7. 爭議與衝突案件

- 涉及會員與問題類型。
- 客觀事件紀錄及雙方陳述。
- 已進行的協調與會議紀錄。
- 委員會決議、負責人及追蹤期限。
- 僅副主席可見的敏感備註。
- 是否需主席或董事顧問介入。
- 結案狀態與必要交接內容。

系統協助保存事實、程序及決議，不自動判斷責任歸屬。

### 8. 代理主席主持

- 本次會議流程與時間。
- 出席及代理人資訊。
- 需要宣布、表決或追蹤的事項。
- 主席交辦內容。
- 主持流程檢核表。
- 會後需回報主席的內容。

### 9. 職務交接

- 職務全貌及固定週期工作。
- 未完成待辦、未結案件與即將到期事項。
- 必要的會員關懷脈絡。
- 資料來源、帳號權責及操作說明。
- 新任副主席上手清單及交接完成度。
- 候任者邀請、權限移轉與卸任者撤權。
- 完整資料匯出及備份。

交接資料需區分可長期保留、限現任職務查看，以及交接後應封存或刪除的敏感內容。

#### 新任副主席教學頁面

- 提供類似線上課程的「新任副主席上手指南」，詳細規格見 `docs/onboarding-course.md`。
- 使用章節、小節與逐頁教學，依實際工作順序帶領新任副主席理解角色與流程。
- 顯示整體及章節進度條，允許閱讀到一半離開。
- 自動保存最後閱讀位置，下次登入可直接繼續。
- 已完成內容可重看，不清除進度。
- 教學進度與群組、權限、案件及資料的實際交接進度分開顯示。
- 看完課程不得自動取得敏感資料權限，也不得自動標記職務交接完成。

##### UI／UX 與視覺呈現

- 整體體驗需像成熟的線上課程平台，不把 Markdown 長文直接搬進網頁。
- 桌面版提供可收合章節目錄、主要閱讀區、章節進度及固定上一章／下一章操作；手機版改為抽屜式目錄。
- 每頁聚焦一個觀念，使用插圖、原生流程圖、比較表、情境卡、檢查清單與重點提示交錯呈現。
- 課程封面及章節情境插圖可使用 image2 製作一致風格的原創視覺；制度文字、表格、流程與數字必須使用 HTML／CSS 原生元件，不畫死在圖片裡。
- 章節切換使用短暫自然動畫，支援「減少動態效果」設定，不使用拖慢閱讀的裝飾動畫。
- 正式規範原文預設收合，主要教學先說明實際操作，需要時再展開來源。
- 保持舒適閱讀寬度、清楚層級、足夠對比、鍵盤操作及行動裝置可用性。
- 不使用真實會員資料製作插圖、範例畫面或測試資料。

### 10. Email 信件與通知

- 保存正式信件公版及版本紀錄。
- 依會員、專業類別、會議與導師資料自動帶入內容。
- 寄送前顯示缺漏欄位及預覽完整信件。
- 第一版先產生 Email 草稿，由副主席確認收件者與內容後寄送。
- 保存寄送狀態、日期、操作者及後續回覆。
- 信件原文與待確認事項另見 `docs/email-templates.md`。

### 11. 制度知識庫與規則引擎

- 保存制度名稱、版本、修訂日、公布日及施行日。
- 每一項系統提醒需能回溯到適用條文及版本。
- 新版守則上傳後，不直接覆蓋舊規則；先顯示差異並由副主席確認生效。
- 把制度條文分為「系統可自動提醒」、「需人工核對」及「由高屏區辦公室最終裁量」。
- 目前制度基準之一為《高屏區會員守則 V9.1》，施行日期 2026-01-01，整理內容見 `docs/policies/member-rules-v9.1.md`。
- 制度來源與既有工具規格不一致時，只顯示差異與建議，不得由系統自行選擇有利或較嚴格的版本。

### 12. 會員委員會投票

- 副主席與當期有效會員委員共同構成投票基數。
- 投票基數動態計算，不固定寫死為 7 人。例如副主席 1 位、會員委員 6 位，基數為 7 位。
- 首頁需顯示當期副主席、會員委員、總基數、待投票案件及尚未投票人數。
- 每次投票開始時保存一份有投票資格者快照，避免任期或名單異動回溯改變歷史結果。
- 系統需保存議案、投票期間、每位有權者的投票狀態、最終票數、通過結果及決議紀錄。
- 新會員、續約及轉換行業別案件需要會員委員會投票；期中輔導與離會訪談不需回饋投票。
- 需投票案件的參與投票人數需超過投票基數的一半；達到參與門檻後，以贊成與反對票多數決。
- 參與門檻公式為 `floor(投票基數 / 2) + 1`。例如基數 7 人，至少 4 人投票。
- 若達到參與門檻但贊成與反對同票，尚未形成決議；例如 7 人基數的前 4 票為 2:2，需等待第 5 人投票。
- 只有申請者／被訪談者本人同時是副主席或會員委員時才強制迴避；主訪、陪訪及案件負責人仍須回饋並保有投票權。
- 會員委員案件介面只顯示訪談 Word、委員回饋與投票；三長群與董事顧問確認、結案存檔、案件狀態及案件歷程由副主席承辦，因此只在副主席介面顯示。
- 訪談 Word 保存後，副主席可從案件流程透過正式 LINE OA 將委員回饋通知送到後台指定的 `committee` 正式群並真正 @所有人；後端以正式案件、訪談資料及當期有效委員名單重建文案，LINE 確認送達後才標記已通知，同案成功後禁止重送。
- 建立投票資格快照後，副主席按下「啟動投票流程」，系統自動產生無登入投票網址及可完整複製的開票公版。副主席原樣貼至委員群後，由會員委員秘書Bot使用該文字事件的免費 Reply API 回覆真正的 @所有人通知及投票圖卡；一般流程不再直接 Push 開票通知。
- 第一版投票頁不要求登入或綁定 LINE 帳號；投票人從本案資格快照選擇自己的姓名，再選擇同意或不同意。這是與原 Google 表單相同的自我申報信任機制，後端仍須執行迴避、資格、截止及每人每案一票限制。
- 正式票採記名保存。副主席／Admin可查閱每位資格者的同意、不同意、未投或迴避狀態；一般會員委員只取得自己的投票選項、整體票數及已投／未投名單，後端不得回傳其他人的選項。
- 投票形成決議後，進行中案件與副主席專用結案資料頁都提供 PNG 結果圖下載；圖面顯示案件、票數、比例、基數、參與門檻、未投人數與產生時間，不列逐人姓名或票向。
- 形成決議後，系統為副主席整理三長群送出資料包：三長群文字文案、投票結果圖、完整訪談內容圖，以及續約案件的一年培訓與來賓數。
- 新會員、續約與轉換行業別只有在投票通過且董事顧問確認同意後，才顯示正式公告群預覽與發布操作；公告使用 LINE OA 純文字訊息，不 @所有人。
- 投票不通過的案件不發布公告群，只保存內部投票、董事顧問確認與結案紀錄。通過案件須在公告群成功送達後才完成結案，發送失敗時保留待公告狀態供副主席安全重試。
- 新會員案件須從既有正式會員主檔搜尋選擇一位引薦人，不接受自由輸入；保存會員識別碼及選擇當下的姓名快照，公告自動帶入該引薦人。轉換行業別公告須帶入鎖定保存的原專業別與欲轉專業別，不得在發布當下才以可能已更新的會員主檔推測舊專業別。
- 完整訪談內容圖必須輸出為單張直向長圖，可在 LINE 中上下滑動閱讀；不得依 Word 頁數拆成多張圖片。
- 五種訪談案件的「已結案」卡都必須有副主席專用的「查看結案資料」入口；結案資料頁統一顯示案件基本資料、正式 Word 下載、適用的委員回饋與投票結果、三長群／董顧確認及案件歷程。
- 期中輔導與離會訪談雖不需回饋投票，結案後仍須能查閱案件摘要並重新下載 Word，不得成為只有狀態而無法開啟的紀錄。
- 棄權、利益衝突迴避、截止時仍平票及人員異動的計算方式尚待確認。
- 詳細需求見 `docs/voting-rules.md`。

### 13. 首頁待辦與多人指派

- 副主席與會員委員登入後，首頁均顯示與自己相關的待辦事項。
- 會員委員首頁預設顯示「我的優先待辦」；待辦包含本人主責／陪訪、本人尚未提交的委員回饋，以及已通知投票但本人尚未投票的案件。
- 同一案件若同時待本人回饋與投票，合併成一張案件卡並提供兩個直達操作；已完成的個人動作不再列為待辦。
- 會員委員可切換「我的待辦」、「我負責的案件」及「分會關注」；副主席／管理員預設保留全體案件管理視角。
- 「我的優先待辦／全體優先案件」位於「本月工作節點」上方，先呈現當下要做的事，再呈現月份規劃。
- 期中關懷等任務可指派 1 至 3 位會員委員，通常為 2 位。
- 每項任務固定指定 1 位主要負責人，其餘 0 至 2 位為陪訪人員。
- 副主席可查看、建立、指派、改派及重新開啟全體任務。
- 主要負責人可查看任務、更新狀態、填寫結果及勾選整體完成。
- 全體會員委員均可查看新會員訪談、期中關懷、續約訪談、轉換行業別訪談及特定會員關懷的進度總覽。
- 主要負責人與陪訪人員可查看執行所需內容並補充紀錄；陪訪人員不能勾選整體完成。
- 未被指派的會員委員可查看進度、負責人、期限及完成狀態，但敏感訪談內容與副主席專屬備註依權限隱藏。
- 首頁需顯示負責人、關懷對象、期限、目前狀態、是否逾期及完成時間。
- 完成操作需保存操作者、時間與必要的關懷結果摘要，不能只有不可追溯的勾選框。
- 多人任務由主要負責人勾選後即視為整體完成，不要求陪訪人員逐一確認。
- 詳細需求見 `docs/task-management.md`。

## 五、新會員與續約申請流程

目前確認的 LINE 公告核准節點：

```text
提出申請
→ 董事顧問確認
→ 會員委員會訪談
→ 會員委員會投票通過
→ 系統產生 LINE 公告
→ 副主席複製並發送至公告群
→ 標記已公告
```

系統需保存各節點的完成狀態、日期、負責人與必要紀錄。董事顧問確認、訪談或投票尚未完成時，不得顯示為可正式公告。

### 新會員入會案件

新會員入會需建立獨立案件，追蹤以下主要階段：

```text
秘書財務提供並確認申請書
→ 移交副主席審核
→ 48 小時內跟進申請者
→ 執事完成審核並於執事會討論核准與否
├─ 未通過：副主席通知申請者與引薦人
└─ 通過：秘書財務通知繳費
   → 執行會計確認刷卡或匯款
   → 秘書財務通知主席安排宣誓
   → 核心幹部在宣誓前領取會員包及 MSP 手冊
   → 秘書財務或副主席送交申請書、訪談表及必要確認圖
   → 中心區辦公室建檔至 BNI Connect
   → 新會員收到一對一資料及電子發票
```

系統需提供 48 小時跟進期限與「下次例會前完成審核」提醒。詳細原文、角色分工、資料欄位、關卡與待確認問題見 `docs/workflows.md`。

### 續約會員案件

續約案件需同時追蹤「提前四個月開始作業」與「到期前 30 日完成全部作業」：

```text
到期前 4 個月由秘書財務拉出名單並通知相關人員
→ 提供續約申請書及確認付款、發票資料
→ 會員委員會審核與續約訪談
→ 通知繳費並由執行會計確認款項
→ 會員委員會討論是否核准
→ 送交續約申請書、訪談表及必要確認圖
→ 中心區辦公室最終審核並完成續約
→ 公告續約完成
→ 8 週內完成 MSP（上）或 MSP（下）任一堂
```

到期前 30 日仍未完成全部作業者，依目前流程視同不續約並開放同專業類別申請。系統不得只以已付款判定續約完成，必須同時確認會員委員會決議、文件送件及中心區辦公室完成狀態。詳細流程見 `docs/workflows.md`。

富聯另有更早的內部管理期限：到期日往前兩個月的 15 日前完成續約申請與繳費。系統以此作為主要行動截止日，並保留中心區「到期前 30 日」為不可逾越的最終期限。例：9 月 1 日到期，富聯內部期限為 7 月 15 日，中心區最後期限依中心區規範另行顯示。

現行制度已無「進階 MSP」課程，系統不得再提供該課程選項。續約會員的培訓要求與新會員不同：續約會員在公告後 8 週內完成 MSP（上）或 MSP（下）任一堂即可；新會員仍依 V9.1 在開通信後兩個月內完成上、下各一次。

## 七、每週點名與 LINE 公告試作（2026-07-14）

- 第一版由 1 至 2 位會員委員在系統逐位手動勾選，不串接 Zoom 自動辨識。
- 點名欄位包含 06:30、07:00、遲到、早退、代理、缺席、是否完成會員簡報、名牌、PIN 章、西裝、開畫面及備註。
- 主要紀錄委員負責確認最終版本，協助點名委員只負責核對；不同紀錄有異議時由會員委員會協調。
- 系統依最新正式半年 PALMS 整理遲到／早退、代理人及缺席累計，再加上該 PALMS 截止日之後、早於本次點名日且已由副主席確認的每週紀錄，最後加上本週現場勾選，依富聯固定格式產生公告預覽；06:30 與 07:00 人數差異不自動判定個人遲到。
- 例如 7/7 已確認的代理紀錄會出現在 7/14、7/21、7/28 的月內累計；下月上傳涵蓋 7 月的新 PALMS 後，7 月週紀錄保留供歷史查閱，但不再疊加，全部累計立即以新 PALMS 為準。
- 每週資料是 LINE 公告的作業紀錄，不得回寫、修正或覆蓋 PALMS；PALMS 與週點名有差異時一律以 PALMS 為正式資料。
- 累計資料未成功載入時，公告必須明確警示並禁止正式發送，不得以空白或零次冒充正式累計。
- 公告中的代理人名單指「由代理人代為出席的會員」，不是實際代理人的姓名。
- 會員簡報秒數做為分會設定，初版預設 25 秒並可切換 30 秒。
- 名牌、PIN 章、西裝與開畫面只作商務環境提醒，不直接列為續約審核條件。
- 主要紀錄確認開放所有會員委員及副主席操作；公告最終確認僅限副主席。
- 已確認週次若發現誤按，僅副主席或 Admin 可重新開啟；重新開啟後先回到草稿狀態，修正完成必須再次通過主要紀錄與副主席雙重確認。
- LINE Bot 尚未串接前，只提供公告複製貼到 LINE；副主席確認後保存週次與公告文字快照，不宣稱已由系統發送。
- 每週 PALMS 回填前置程序：秘書財務先在 BNI Connect 登錄來賓姓名及邀請會員等資料；副主席後台出現該批資料後完成確認，才正式納入來賓紀錄。副主席開始當週 PALMS 作業前須先向秘書財務確認登錄完成，避免遺漏來賓數。

### LINE Bot 測試群串接（2026-08-08）

- 保留「複製公告貼到 LINE」作為平台異常時的人工備援，並在同一操作區增加 Bot 發送按鈕。
- 未完成最終確認的草稿不得發送；重新開啟週次後，發送按鈕再次鎖定，直到新版公告完成雙重確認。
- 發送內容以 Supabase 保存的確認快照為唯一來源，前端只傳週次日期，避免瀏覽器竄改公告文字。
- 發送權限只開放副主席與 Admin；群組必須先由已驗證 LINE Webhook 發現，再由副主席／Admin 於系統中明確核對為測試群。
- Webhook 不保存聊天內容；所有 LINE Secret 只位於 Supabase Edge Function Secrets。
- 發送紀錄必須可稽核且阻擋同一版本重複發送；失敗時準確呈現原因，不得假裝成功。
- 正式群啟用為另一個人工確認階段；測試群不得自動升格或被新偵測群組取代。
- 後台提供「每週出席公告、會員委員會通知、三長／董顧通知、交流群常態通知」四個用途槽位，由副主席／Admin 將 Webhook 發現的群組明確指定為測試或正式群；2026-08-19 起改由下方兩個官方帳號分工，不再全部共用同一 Bot。
- 每個用途同時只能有一個啟用群組；改指定時自動停用原群組，功能頁依用途由後端解析目標，不接收前端提供的 LINE group ID。
- 人工停用只解除用途綁定，不刪除群組；只要 Bot 仍在群組內，該群組必須留在「可指定群組」並可立即重新啟用。若 Bot 已離開群組，則先重新加入並傳送一則訊息後才能指定。
- 每週出席公告的 Bot 訊息開頭使用 LINE `textV2` 全群 mention，實際觸發「@所有人」通知；不得只在純文字中偽裝成 `@all`。
- 目前 Bot 對群內一般訊息保持靜默：LINE OA 的聊天與自動回應關閉、Webhook 開啟。未經另行確認不得加入廣泛自動回覆；未來若新增特定文字回覆，須限定觸發條件、適用群組與內容。

### 兩個 LINE 官方帳號分工（2026-08-19）

- 「副主席秘書Bot」只負責 `attendance`、`leadership`、`exchange`；「會員委員秘書Bot」只負責 `committee`，兩者使用獨立 Channel Secret、Access Token 與免費訊息額度。
- 會員委員秘書Bot的每月委員會提醒、工作摘要及案件回饋維持既有 Push 流程；案件開票通知是例外，2026-08-28 起改由副主席貼出系統完整公版，Bot以該文字事件的 `replyToken` 免費回覆投票圖卡。
- `committee` 訊息繼續使用 LINE `textV2` 真正 @所有人，並沿用既有文案來源、正式群限制、retry key、防重複及送達後才推進案件狀態等規則。
- Webhook 必須用收到請求之 OA 的 Channel Secret 驗證簽章，只保存群組 ID、時間與所屬 OA，不保存聊天內容；群組摘要與訊息發送一律使用該群所屬 OA 的 Access Token。
- 系統設定頁必須顯示群組由哪一個 Bot 發現，且後端強制 `committee` 只能綁定會員委員秘書Bot，其餘三條路由只能綁定副主席秘書Bot。
- 拆分前由副主席秘書Bot綁定的會員委員會群不得自動改認為新 Bot；須解除舊路由、邀請會員委員秘書Bot入群、產生新事件，再由副主席／Admin 明確核對。

### 交流群常態通知（2026-08-08）

- 新增副主席／Admin 專用的獨立功能頁，不混入每週點名操作頁。
- 每週例會提醒可由使用者設定星期、發送時間與可修改文案，內容提醒夥伴隔天例會並設定鬧鐘。
- 月底數據提醒依當月最後一次固定例會日自動推算；可設定例會星期、提前天數、發送時間與文案，提醒夥伴完成 BNI Connect 數據 Key in。
- 兩項提醒各自有啟用開關，初始一律關閉；未綁定 `exchange` 群組時禁止啟用。設定保存不等於立即發送。
- 頁面提供 LINE @所有人預覽、人工測試與最近發送紀錄。人工測試會真實送到交流群，必須顯示群名並二次確認。
- 月底 Key in 卡片保存後顯示後端推算的「下次提醒時間」（日期、星期及時間）；未啟用時須明確標示不會自動發送。
- 排程由 Supabase 執行，須以獨立 secret 驗證；不依賴副主席電腦或瀏覽器保持開啟。
- 同一提醒、當地日期與目標群組只能建立一次排程發送；成敗、LINE request ID、訊息雜湊與 retry key 均保存於 service-only 稽核資料。

### 會員委員會群每月會議提醒（2026-08-08）

- 與交流群提醒共用「常態通知」頁，但後端固定解析 `committee` 路由，不得誤送至 `exchange`。
- 每月只發送一次：依固定例會星期推算當月第一次例會，於前一天的指定時間提醒會員委員隔天例會後召開委員會會議。
- 若當月第一次例會為每月 1 日，提醒日會落在上個月最後一天；排程不得因跨月而漏發。
- 副主席／Admin 可調整固定例會星期、發送時間及文案；提醒初始關閉，未綁定會員委員會群時禁止啟用。
- 人工測試必須顯示實際會員委員會群名稱並二次確認，訊息使用 LINE 全群 mention；發送紀錄與防重複機制沿用常態通知稽核資料。
- 卡片保存後顯示後端推算的「下次提醒時間」（日期、星期及時間），且跨月顯示必須與正式排程一致；未啟用時仍顯示預計值但不得暗示一定會發送。

### 每週會員委員會工作進度（2026-08-10）

- 與其他提醒共用「常態通知」頁，但此項不自動排程發送；副主席／Admin 必須先看到系統依正式案件產生的完整排版。
- 資料只讀 Supabase 未完成案件，包含案件類型、會員、主要負責人、全部陪訪人員、期限及目前流程階段；完整姓名不得縮成頭像字或「陪訪 1 位」。
- 統計固定顯示「目前進行中 N 件」及「逾期 N 件｜回饋中 N 件｜投票中 N 件」，案件依期限及類型分組。
- 公版不顯示「以上案件目前皆為訪談草稿進行中」；結尾提醒主責與陪訪委員留意期限，排程或分工需調整時在群組提出。
- 副主席可在預覽區修改文字；按下發送前須顯示後台已指定的 `committee` 群名稱、測試／正式環境並二次確認，訊息使用 LINE `textV2` 真正 @所有人。
- 預覽保存案件、分工、期限與流程版本的來源指紋；任一資料更新即阻擋舊預覽。相同日期、正式群組及相同文案不得重複成功發送。
- 稽核保存操作人、時間、來源與文案雜湊、retry key、LINE request ID 及成敗，不保存完整文案或群組聊天內容。

### 案件開票呼喚與無登入系統投票（2026-08-08／2026-08-28）

- 適用新會員、續約與轉換行業別三種需正式決議的案件；只有副主席可在開啟投票後操作。
- 文案依案件類型顯示「新申請投票／續約投票／轉換行業別投票」，並帶入申請者姓名、專業別及正式投票快照截止時間。
- 後端固定解析 `committee` 路由且環境為 `production` 的會員委員會群，前端不得傳入 LINE group ID、姓名、專業別或任意通知文案。
- 副主席按下「啟動投票流程」後，系統建立投票資格快照、不可猜測且隨截止時間失效的無登入投票網址，以及一份含一次性呼喚識別與文案指紋的完整公版；剪貼簿與後端交易成功後進入待回覆狀態，Bot Reply 成功後才開放送票。
- 副主席須將完整公版原樣貼到會員委員會正式群。Webhook只接受會員委員秘書Bot收到的群組文字事件，並同時驗證正式群、呼喚識別、正規化文案指紋、案件快照及截止版本；不得以姓名或部分關鍵字模糊比對。
- 驗證成功後，Bot以事件的 `replyToken` 在同一次 Reply API 請求送出 LINE `textV2` 真正 @所有人通知與 Flex 投票圖卡。正常開票不使用 Push，因此不消耗輕用量方案的月訊息額度。
- 投票圖卡及人工公版中的網址都進入同一份極簡無登入投票頁。頁面只列出本案有效資格快照姓名、同意／不同意及確認送出；不要求 Supabase 共用帳密，也不要求 LINE 帳號綁定。
- 後端依投票人自行選擇的姓名寫入既有正式投票資料，仍強制申請者迴避、資格快照、截止時間、每人每案一票及既有票不可自行修改。稽核另標示來源為 LINE 無登入投票，不得假冒 Supabase 登入使用者。
- 複製成功只顯示「待貼到委員群／待 Bot 回覆」，網址尚不收票；Reply成功後才標示「投票圖卡已回覆」並開放同一網址。Reply失敗時，重新貼上同一份完整公版取得新的 `replyToken`，不另建第二份投票或消耗 Push 額度補送。
- Webhook只暫時解析命中的系統公版，不保存完整群組聊天文字；service-only 稽核保存案件、快照、群組、呼喚識別雜湊、文案雜湊、`webhookEventId`、LINE message ID、時間及回覆成敗。Webhook重送與同文重貼不得重複回覆圖卡。
- 投票截止時間或文案版本更新時，投票網址、呼喚識別、文案指紋、複製紀錄及回覆紀錄全部失效，必須產生新版公版重新貼送。
- 既有歷史案件若已存在人工／模擬通知紀錄，不自動補發正式 LINE，避免重複打擾群組。
- 上線前須有與正式群隔離的會員委員會測試群。設定頁提供獨立測試器，可選擇一位既有會員作為畫面顯示對象，完成從複製呼喚文案、測試群 Bot Reply圖卡、無登入投票到後台票數的端對端驗收。
- 測試器不建立正式案件、訪談 Word 或正式票；測試呼喚、票數及通知稽核不得計入正式投票、待辦、工作摘要或對正式群的任何通知。驗收完成後，Admin／副主席可清除該次測試資料，不影響會員主檔及其正式歷史。

## 八、SaaS 與資料交接原則

- 使用者透過網址及個人帳號登入。
- GitHub 保存程式碼並支援自動部署。
- 會員資料、關懷紀錄、原始報表及案件資料存放於受控的雲端資料庫或檔案儲存，不進入公開程式碼倉庫。
- 分會需持有最高管理權與帳號復原方式，不綁定單一副主席的私人帳號。
- 需要登入、角色權限、操作紀錄、備份、資料匯出及離任撤權。
- 系統應能檢查報表是否齊全、最近備份日期、未結案件與交接完整度。

## 九、待補資料與待確認問題

- 副主席每週、每月、每季實際工作清單及期限。
- 會員委員會投票基數、過半參與、多數決及記名查閱權限已確認；棄權、其他利益衝突迴避、截止平票及高風險案件門檻仍待確認。
- 新會員、期中關懷、續約、轉換行業別及離會訪談表已提供；各表必填欄位、通過判斷標準、正式版本及簽名方式仍待確認。
- 遲到、缺席當責信的正式門檻、公版文字及寄送方式；代理當責信已確認第 6、7、8、9 次逐次寄發，各級正式公版仍待提供。
- 專業類別確認與爭議處理的實際流程。
- 代理主席主持會議的議程與檢核表。
- 哪些事項必須回報主席，哪些必須回報董事顧問。
- 敏感案件資料的保存年限及可見範圍。
- SaaS 的實際技術架構、網域、帳號持有人與維運責任。
