# 產品版本編碼規則

本規則只管理使用者在工作台看到的產品版本（例如 `v1.0.25`），不等同於總專案 `package.json` 的開發工具版本。

## 歷史基準

- `v1.0.0` 至 `v1.0.25` 是早期依發布順序累加的歷史版本，全部保留，不追溯重編。
- `v1.0.25` 是新規則的基準點。建立規則、文件、測試或部署紀錄本身不改變使用者功能，因此不為此另外升版。
- 從下一次實際產品發布開始，採 `主版號.功能版號.修正版號`。

## 升版判定

| 變更類型 | 使用時機 | 升版方式 | 以 `v1.0.25` 為例 |
|---|---|---|---|
| `feature` | 新增使用者看得到或用得到的功能、流程、頁面或能力 | 功能版號加 1，修正版歸零 | `v1.1.0` |
| `fix` | 相容的錯誤修正、安全強化、時區或資料完整性修正 | 修正版號加 1 | `v1.0.26` |
| `breaking` | 舊資料、API、登入或主要操作流程無法相容的世代改版 | 主版號加 1，其餘歸零 | `v2.0.0` |
| `none` | 只有文件、測試、內部重構、部署紀錄，且使用者行為沒有改變 | 不建立新產品版本 | 維持 `v1.0.25` |

同一批發布若同時含多種類型，採影響最高者：`breaking` ＞ `feature` ＞ `fix` ＞ `none`。同一次發布可以包含多個新功能，不需要每個功能各跳一個版本。

版本號的三段都是整數，不是小數；因此 `v1.10.0` 會晚於 `v1.9.0`，不會被解讀成 `1.1`。

## 唯一來源與使用方式

- 計算與驗證唯一來源：`core/version-domain.mjs`
- 目前已發布版本狀態：`release-version.json`
- 使用者版更新內容：`assets/js/release-notes.js`
- 人工預覽下一版：`npm run version:next -- feature`（也可傳入 `fix`、`breaking`、`none`）

正式發布新版本時：

1. 先依本表判定變更類型；混合發布交給工具取最高層級。
2. 用工具算出下一版，不自行以發布次數連號。
3. 在 `release-version.json` 記錄前一版、目前版與變更類型。
4. 同步更新 `assets/js/release-notes.js`、技術 `CHANGELOG.md` 與必要的部署紀錄。
5. 執行完整測試；版本狀態、更新紀錄第一筆與升版轉換不一致時不得發布。
