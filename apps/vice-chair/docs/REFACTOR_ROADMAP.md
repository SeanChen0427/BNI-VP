# 重構路線圖

更新日期：2026-09-06

定位：系統已正式運作；本文件記錄已完成基礎、尚在收斂的技術債與後續治理，不再作為「上線前待辦」。

目標不是一次重寫，而是在功能持續增加時降低遺漏、除錯與 AI 上下文成本，同時保護正式資料、本機復原能力與完整歷史。

狀態定義：`完成` 表示現行正式基礎已具備；`進行中` 表示已有實作但仍有明確缺口；`未開始` 表示尚無可靠實作；`延後評估` 表示目前不應投入。

## 第 0 階段：建立地圖與護欄

狀態：完成。

- 已建立總專案與工作台 `project-manifest.json`。
- 已建立 AI 開發入口、架構圖、儲存 schema 與跨模組健檢工具。
- 現行需求、決策與未決事項已有唯一文件；歷史部署、變更與審查紀錄保留追溯。
- 已建立案件共用 domain 與自動測試，跨模組修改由 `npm run check` 驗證。

## 第 1 階段：格式化與共用規則

狀態：進行中；低至中風險。

1. `未開始`：導入 Prettier 或 Biome，分批格式化高密度 CSS／JS；不得把全庫格式化與功能修正混在同一批。
2. `進行中`：案件類型、表單路由與階段規則已集中至 `core/case-domain.js`，其他領域也已有共用 domain；仍需在修改相關功能時移除殘留重複定義。
3. `進行中`：主要案件 Key 已集中，但瀏覽器快取、個人狀態與舊版搬移 Key 尚未收斂到單一登錄表／服務。
4. `完成`：投票門檻、迴避與結果判定已有共用規則與回歸測試；正式後端另執行資格與唯一票驗證。
5. `完成`：舊課程程式已移至 `archive/legacy/`，正式頁面不再載入。

完成標準：相同業務規則只有一個可驗證的定義位置；搜尋到的其他位置只能是消費者、歷史紀錄或相容轉接。

## 第 2 階段：儲存服務與資料模型

狀態：進行中；正式後端已完成，瀏覽器相容層仍待收斂。

- `進行中`：任務、案件狀態、附件與主要資料已有專用 store／service／Edge API；少數頁面仍直接操作瀏覽器儲存。
- `完成`：正式 Case、Interview、Feedback、Vote、Attachment 等資料已拆入 Supabase schema、Private Storage 與版本化狀態，不再以單一巨大本機 JSON 作正式來源。
- `進行中`：Supabase migrations 已版本化；舊版 `localStorage`、課程進度與個人狀態仍需在實際修改時逐項補齊 schema／migration。
- `完成`：正式刪除、結案、換屆、指派與附件清理由後端權限、事件／歷程及清理工作保護；新增流程仍須沿用相同交易邊界。
- `未開始`：完整本機復原副本的固定匯出、加密、線上差異核對與隔離還原演練。此項是資料持續性 P0，不等同於瀏覽器快取。

完成標準：正式資料只以 Supabase 為日常權威；本機復原副本可用版本與核對證據證明完整，且更換儲存方式不需逐頁修改。

## 每次重構的限制

- 一次只處理一個邊界，先確認正式資料與歷史相容影響。
- 先寫或確認相容測試，再替換消費者。
- 不把新產品需求混入純重構。
- 保留舊資料 migration、已發布快照、決策、CHANGELOG 與日期化部署證據，不讓現有草稿或追溯鏈消失。
- 任何本機／線上同步不得採人工雙寫；先定義權威來源、版本、差異檢查與衝突處理。
- 完成後更新 manifest、現況文件與 CHANGELOG；已完成事項從 `OPEN_QUESTIONS.md` 移出，但歷史證據不刪除。
