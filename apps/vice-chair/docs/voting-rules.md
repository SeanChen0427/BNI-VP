# 會員委員會投票規則草案

狀態：需求蒐集中  
建立日期：2026-07-10

## 一、已確認原則

會員委員會需要針對新會員、續約及其他需決議事項進行投票，因此副主席與會員委員名單同時也是投票資格名單。

```text
投票基數 = 1 位當期副主席 + 當期有效會員委員人數
```

例如：

```text
副主席 1 位 + 會員委員 6 位 = 投票基數 7 位
```

7 位只是目前常見範例，不是系統固定值。換屆、人員退出、補任或委員人數改變時，基數必須依當期有效名單重新計算。

## 二、通過規則

新會員、續約及其他會員委員會表決採兩階段判定：

### 第一階段：達到最低參與人數

```text
最低參與人數 = floor(投票基數 / 2) + 1
```

也就是參與投票人數必須超過全體投票基數的一半。

| 投票基數 | 最低參與人數 |
|---:|---:|
| 5 | 3 |
| 6 | 4 |
| 7 | 4 |
| 8 | 5 |
| 9 | 5 |

未達最低參與人數時，即使目前贊成票較多，也不能形成正式決議。

### 第二階段：多數決

達到最低參與人數後，贊成票與反對票以票數較多者為結果。贊成與反對同票時，尚未形成決議；若仍有具投票資格者尚未投票，需繼續等待下一票。

例如投票基數為 7 人：

- 3 人投票：未超過半數，不能形成決議。
- 4 人投票，3:1：已達 4 人門檻，贊成票較多，可形成通過決議。
- 4 人投票，1:3：已達 4 人門檻，反對票較多，可形成不通過決議。
- 4 人投票，2:2：雖已達參與門檻，但票數相同，必須等待第 5 位投票者。
- 5 人投票，3:2：贊成票較多，可形成通過決議。

系統需分開顯示「已達參與門檻」與「多數決結果」，不得把兩者合併為單一進度。

## 三、首頁呈現

副主席與會員委員登入後，首頁應看到：

- 當期副主席姓名。
- 當期會員委員名單。
- 委員會有效人數及投票基數。
- 目前待投票案件數。
- 每個案件的投票截止時間。
- 已投票人數與尚未投票人數。
- 最低參與人數及目前是否達標。
- 目前贊成、反對票是否已形成多數，或仍為平票。
- 自己尚未完成的投票。
- 已結束但尚待副主席確認決議的案件。

副主席另可看到名單異常，例如任期未設定、委員已停用但仍在投票名單，或案件開啟後有人員異動。

## 四、人員與任期

每一位副主席或會員委員至少需保存：

- 系統帳號。
- 姓名。
- 職務：副主席或會員委員。
- 任期開始日與結束日。
- 是否具有投票權。
- 啟用、停權、退出或補任狀態。
- 狀態變更日期與原因。

登入權限與投票資格需分開判定。例如帳號暫時無法登入，不代表歷史投票名單可被刪除；已卸任者也不可因帳號仍存在而參加新投票。

## 五、投票資格快照

每個案件開啟投票時，系統保存當下有資格投票的副主席與會員委員名單，作為該案投票基數快照。

快照至少包含：

- 投票案件編號。
- 開啟時間及截止時間。
- 當期職務與任期。
- 有資格投票者名單。
- 原始投票基數。
- 投票期間的人員異動與處理方式。

投票結束後，即使後續換屆，也不得回溯改寫歷史基數、票數或投票人身分。

## 六、投票案件

案件至少需記錄：

- 案件類型，例如新會員、續約或其他會員委員會決議。
- 提案內容及必要附件。
- 可查看的案件摘要。
- 投票開始與截止時間。
- 有資格投票者快照。
- 每位投票者是否已投票。
- 贊成、反對、棄權或其他正式選項。
- 最終票數與決議。
- 最低參與人數、實際參與人數及門檻達成狀態。
- 贊成、反對票數及是否平票。
- 副主席確認日期。
- 與 LINE 公告、Email、繳費或送件流程的銜接狀態。

敏感案件應依角色及案件分派限制可見內容。每張正式票都需保留投票者姓名與選項供稽核；只有副主席及系統開發人員 Admin 可查閱全體逐人票向。一般會員委員只可取得自己的選項、整體同意／不同意票數，以及哪些資格者已投／未投，不得由前端或後端取得其他人的選項；申請者迴避期間不得取得該案票數或票向。

### 委員回饋 LINE 通知

- 新會員、續約與轉換行業別訪談 Word 保存後，副主席按下「啟動回饋流程並複製文案」，系統依 Supabase 正式案件、訪談資料及當期有效委員名單建立一次性免登入回饋網址與完整公版；一般流程不再直接 Push 回饋通知。
- 副主席可明確選擇會員委員會測試群或正式群，再將完整文案原樣貼到該次指定群組。Bot 僅在群組、一次性識別及完整文案雜湊全部相符時，以該事件的 Reply API 回覆真正 @所有人通知及 Flex 回饋圖卡，不使用一般 Push 額度；同文貼到另一群不得觸發。
- 測試群／正式群只決定圖卡發布位置。兩者都固定連回同一份正式案件與正式 `case_feedback`，不得建立「測試回饋」或顯示為不列入正式紀錄；選擇測試群前須二次確認。
- 第一版不綁定 LINE 帳號，也不要求登入系統。委員從本案有效名單自行選擇姓名並填寫回饋，沿用原 Google 表單的自我申報信任程度；後端仍排除申請者本人、非名單姓名、已結案案件及同一姓名重複送出。
- **打開免登入回饋頁後，所有委員都可立即查看目前全體回饋，不必先送出自己的內容。**這是已確認的協作方式，不設「先填才能看」的門檻。
- 公開頁本人送出後即寫回既有正式回饋紀錄。若該姓名只有副主席代填內容，本人可用公開頁取代代填版本；若已由本人送出，公開頁不得再次覆蓋，需聯絡副主席處理更正。
- 送出完成後提供 LINE 分享與複製按鈕，讓委員自行把內容貼回會員委員會群延續討論；分享動作不影響系統已保存的正式回饋，也不由 Bot 代為公開逐筆內容。
- Webhook 可暫時解析命中的完整文案，但不保存群組聊天內容；資料庫只保存案件、名單快照、群組、Token／文案雜湊、LINE event／message ID、時間與回覆結果。Bot Reply 成功後網址才開放填寫，失敗時可將相同完整文案重貼到同一群組安全重試。
- 來源：富聯現行 LINE 群組回饋公版；Sean 2026-08-28 確認改為呼喚 Bot 免費回覆免登入回饋圖卡、直接同步正式案件，並明確決定委員不需先送出即可看到其他人的回饋。

### 開票通知與系統投票開放

- 新申請、續約與轉換行業別建立投票資格快照後，副主席按下「啟動投票流程」，系統自動產生無登入投票網址及一份可完整複製的開票文案；一般流程不再直接 Push 開票通知。
- 文案由 Supabase 正式案件及投票快照帶入案件類型、申請者、專業別、截止時間及系統投票網址，並保留富聯現行公版的提醒文字。範例只能使用去識別化姓名與資料，不得把真實案件寫入 GitHub。
- 文案內含一次性呼喚識別及正規化文案指紋。副主席啟動流程時預設選擇正式群，也可明確選擇測試群，再將文案原樣貼到該次指定的會員委員會群。Bot 不得只以申請者姓名、專業別或部分關鍵字模糊比對案件。
- Webhook 僅接受會員委員秘書Bot、本次呼喚綁定的 `committee` 測試群或正式群、`message`／文字事件及有效 `replyToken`。呼喚識別、群組、案件快照、截止版本與文案指紋全部相符後，Bot才以 Reply API 回覆真正的 @所有人通知及投票 Flex 圖卡；這是回覆訊息，不使用一般 Push 額度。同一文案貼到另一個群組不得觸發。
- 複製成功後，後端交易式保存操作人、複製時間、截止版本、投票網址版本及文案指紋；畫面顯示「待貼到委員群／待 Bot 回覆」，此時網址尚不收票且不得冒充 OA 已回覆。Bot成功回覆後才開放送票，並保存「投票圖卡已回覆」及 LINE 稽核欄位。
- 投票圖卡與人工文案中的按鈕／網址都指向同一份無登入投票頁。第一版不綁定 LINE 帳號，投票人從本案有效資格快照選擇自己的姓名並選擇同意或不同意；系統接受與原 Google 表單相同的自我申報信任程度。
- 無登入不代表取消案件規則：後端仍須排除申請者及其他正式迴避者、拒絕不在資格快照中的姓名、每位每案只接受一票，並在截止後停止收票。既有票若需更正，仍須由 Admin 留存原因處理。
- Webhook 可暫時讀取該則文字以驗證呼喚識別及正規化文案指紋，但不得保存完整群組聊天內容；只保存案件、快照、文案雜湊、群組、`webhookEventId`、LINE message ID、時間及回覆成敗。Webhook重送或同文重貼不得產生第二張圖卡。
- 若 Bot 回覆失敗，副主席將同一份完整文案重新貼到相同群組以取得新的 `replyToken`；該網址在 Reply 成功前維持鎖定，不另建第二份投票。投票截止時間或文案版本更新時，舊網址、舊呼喚識別、舊文案指紋及既有回覆狀態全部失效，須重新複製與貼送。
- 測試群／正式群只決定 Bot 回覆圖卡的位置。無論選擇哪一個群，呼喚都固定屬於正式案件及正式投票快照，送票寫入同一份正式 `votes` 並影響決議與結案；選擇測試群前必須二次確認，不得顯示成「不列入正式紀錄」。
- 來源：富聯現行 Google 表單開票公版；Sean 2026-08-28 確認改以人工貼出完整文案呼喚 Bot 免費回覆投票圖卡，並以系統無登入投票頁取代逐案建立 Google 表單；同日確認正式案件可明確選擇測試群作為小規模發布位置，但票仍是正式票。

### 上線驗收完成與測試器退場

- 2026-08-28 已在獨立測試群完成呼喚公版、Bot Reply圖卡、無登入選名與送票、重複送票阻擋、正式系統同步、具名票向與結果圖驗收。
- 驗收完成後，設定頁的 LINE 投票測試器、測試呼喚 API、測試圖卡與測試票寫入路徑全部退場；舊測試連結不再收票。
- 正式開票只允許從正式案件產生；副主席可選擇已核對的 `test` 或 `production` 會員委員會群觸發圖卡，兩者都固定寫入正式案件、正式資格快照及正式票。
- LINE 群組管理的通用測試群環境不能自行建立投票測試呼喚或測試票；只有正式案件在啟動流程時明確選擇該測試群，才可觸發該案的正式投票圖卡。
- 來源：Sean 2026-08-28 確認正式功能已上架且測試無誤，指示移除 LINE 投票測試器；同日後續指定保留正式案件選擇測試群發布的能力。

### 具名票向與投票結果圖

- 正式投票採記名保存，副主席及系統開發人員 Admin 可在進行中案件查閱每位資格者的同意、不同意、尚未投票或迴避狀態；副主席也可在已結案資料頁再次查閱。
- 一般會員委員畫面可顯示整體票數與已投／未投狀態，但後端只回傳該登入姓名自己的投票選項，不回傳其他人的同意或不同意。
- 投票形成通過或不通過決議後，副主席可從進行中案件或已結案資料頁下載 PNG 投票結果圖，供三長群／董事顧問確認使用。
- PNG 圖面包含案件類型、申請者、專業別、截止時間、投票基數、最低參與、已投、未投、同意／不同意票數、比例、目前決議與產生時間；圖面不列投票者姓名或逐人票向。
- 每次下載都依當下正式票數重新產生並標示產生時間；如後續仍有資格者投票，先前下載圖不自動更新，副主席應重新下載後再轉傳。
- 來源：富聯現行 Google 表單結果截圖作業；Sean 2026-08-28 確認董顧需要整體投票結果圖，且副主席須能回答反對票由誰投下。

### 董事顧問確認後的公告群發布

- 新會員、續約與轉換行業別案件，只有投票結果為通過且董事顧問確認同意後，才由副主席發布正式結果到公告群。
- 不通過案件不發布公告群；內部投票、董事顧問確認與結案稽核仍完整保存。
- 正式結果公告不使用 @所有人，末尾固定顯示「（只讀不回）」。
- 通過案件依序完成三長群、董事顧問確認及公告群發送；LINE 成功送達後才能完成案件結案。發送失敗不得誤標為已公告，並須允許安全重試。
- 新會員公版包含申請者、專業別與引薦人；引薦人必須從既有正式會員主檔選擇並保存會員識別碼與姓名快照，不接受自由輸入。續約公版包含申請者及專業別；轉換專業別公版包含申請者、原專業別及欲轉專業別。
- 同一案件與公告版本不得重複發送；若已公告內容需要修正，應另建更正公告並保留原公告與操作歷程，不得靜默覆蓋。
- 來源：富聯現行作業公版；Sean 2026-08-10 明確確認不通過案件不公告。

## 七、申請者本人強制迴避

若新會員、續約或其他申請案件的申請者本人是會員委員，該員必須迴避；申請者本人是副主席時亦同。

主訪委員、陪訪委員及副主席若只是本案訪談執行者，仍屬有效回饋及投票人員，不因參與訪談而迴避。系統不得以主訪、陪訪或案件負責人身分排除資格；迴避判定只比對申請者本人是否為當期副主席或會員委員。

### 群組與資料隔離

1. 案件回饋及投票開始前，申請者暫時退出會員委員會 LINE 群組。
2. 迴避期間不得查看該案件的委員回饋、內部討論或票向。
3. 投票及該案內部討論完成後，才能重新加入會員委員會群組。
4. 系統保存迴避開始、退出群組、投票完成、重新加入群組的時間與執行人。

### 投票基數

- 申請者不列入該案件的有效投票基數，亦無該案投票權。
- 最低參與人數依扣除申請者後的有效基數重新計算。
- 例如原基數為 7 人，1 位申請者迴避後有效基數為 6 人，最低參與人數為 `floor(6 / 2) + 1 = 4` 人。
- 投票資格快照需同時保存原始當期名單、迴避者、迴避原因及調整後有效基數。

若申請者是副主席，由哪一位委員代理開啟投票、管理群組退出與重新加入，尚待指定；在代理人確定前不得由申請者本人操作該案。

## 八、系統安全原則

- AI 不得代替人員投票，也不得自動作成通過或拒絕決議。
- 副主席可依會員委員透過 LINE 提供的文字代填該委員的案件回饋，系統必須保存回饋歸屬人與實際代填者；此授權不延伸至投票，副主席不得代替任何人投票。
- 已投票紀錄不得由一般使用者修改；若需更正，必須保存原因、時間與操作紀錄。
- 投票截止後不得新增票，除非依正式程序重新開啟並留下紀錄。
- 系統不得因目前人數改變而回算歷史投票。
- 投票結果尚未符合已確認規則時，只顯示票數，不自行標示通過。
- 達到最低參與人數但贊成與反對同票時，不得標示通過或不通過。

## 九、待確認規則

- 副主席是否在所有案件都有一票，或特定案件只主持不投票。
- 棄權是否計入基數及通過門檻。
- 未投票及逾期未投票如何處理。
- 申請者本人已確認必須迴避；引薦人、親屬、商業合作或其他利益衝突是否同樣強制迴避仍待確認。
- 投票期間有委員退出、停權或補任時，該案快照是否調整。
- 終止資格等高風險案件是否同樣採一般多數決，或另有更高門檻與中心區核准程序。
- 投票截止或全體完成投票後仍平票時如何處理。
- 最終結果由副主席確認、會員委員會會議確認，或另需董事顧問／中心區確認。
