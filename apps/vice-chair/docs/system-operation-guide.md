# 富聯工作台全站系統操作導覽規格

狀態：v1.1.1 已實作並完成本機驗證
建立日期：2026-09-05
適用範圍：`apps/vice-chair/` 的副主席／會員委員工作台、案件、表單、公開回饋／投票、資源、設定與學習頁面；Admin 明確排除

## 一、產品定位

本功能名稱為「系統操作導覽」，與既有「新任副主席上手指南」完全分離：

- 新任副主席上手指南：說明制度、角色、責任與業務判斷。
- 系統操作導覽：在真實頁面上逐一指出功能位置、按鈕用途、操作順序、資料影響與角色限制。

系統操作導覽不是簡化版說明頁，也不是一次性的歡迎輪播。它是一套內嵌於產品的完整引導層：第一次登入時介紹全站共同介面；第一次進入每個頁面時自動啟動該頁完整導覽；之後可由固定入口隨時重看。

本功能不得重寫案件、投票、計分、表單或權限邏輯，只能讀取既有畫面狀態並提供說明。

## 二、已確認需求

1. 使用者第一次登入後，自動開始全站大方向導覽。
2. 全站導覽需完整介紹目前角色可見的左側工作選單、子選單、頁首共同操作、回首頁／上一頁、版本更新、身份、通知及教學入口。
3. 全站導覽完成後直接解除遮罩並回到可操作的工作總覽，不得立即串接第二份導覽封面。
4. 首頁儀表板與其他工作頁一樣保有獨立完整導覽；使用者之後第一次重新進入該頁，或由「操作教學」主動選取時，再介紹各區塊、數字、篩選器、按鈕與使用方式。
5. 每一個可操作控制都必須納入導覽覆蓋矩陣。相同目的的欄位可合併為一個教學步驟，但不得漏掉任何按鈕、連結、切換、篩選、表單區段或動態操作。
6. 不同角色只介紹其實際可見且有權限使用的功能；不得向會員委員展示副主席或 Admin 專屬操作。
7. 導覽必須符合現有系統的專業產品感，不採用卡通人物、廉價對話泡泡、螢光色外框、彈跳動畫、過度遊戲化或第三方元件的預設外觀。
8. 每個頁面都提供永久可見但不干擾工作的「操作教學」入口，能重看本頁、重看全站、繼續中斷進度及查看新增功能。
9. 新增功能必須有獨立版本與新增功能導覽；不得要求已完成使用者無條件重看整頁。
10. 導覽進度與副主席制度課程進度分開保存、分開顯示。
11. 副主席與會員委員使用兩套依權限產生的內容；Admin 不建立導覽身份、不載入工作頁導覽，也不顯示操作教學入口。
12. `login.html` 因登入前尚無角色且控制精簡，列為自明操作豁免；登入成功後才依角色啟動全站導覽。
13. 換屆後同一人角色未改變時沿用原進度；副主席與會員委員角色互換時只看一次新角色差異，已看過的共同頁面不重播，新角色專屬且尚未看過的頁面仍在首次進入時教學。

## 三、盤點基線與完成定義

截至 2026-09-05，工作台共有 22 個 HTML 頁面；靜態 HTML 已包含：

- 134 個 `button`。
- 82 個 `a`。
- 144 個 `input`。
- 41 個 `select`。
- 55 個 `textarea`。

以上尚未包含 JavaScript 依角色、案件、資料與流程階段動態產生的按鈕、卡片操作及對話框。

「完整導覽」的驗收定義不是導覽能播放，而是每個可操作元件都有以下其中一種狀態：

1. `covered`：已由全站、頁面、區段或動態功能導覽介紹。
2. `grouped`：與相同目的的欄位群組共同介紹，覆蓋矩陣記錄其所屬步驟。
3. `conditional`：只在特定角色或狀態出現，第一次真正出現時啟動補充導覽。
4. `exempt`：純瀏覽器原生、隱藏資料欄位或不應由使用者直接操作；必須記錄豁免理由。

任何按鈕或控制沒有上述狀態，都視為該頁導覽未完成。

## 四、使用者體驗架構

### 4.1 第一次登入

登入驗證完成、姓名與角色確認後，先顯示品牌化歡迎畫面：

- 標題：`歡迎使用富聯會員委員會工作台`
- 說明：本次會先認識工作區；首頁及各工作頁另有自己的完整導覽，可中途離開並從原處繼續。
- 顯示預估段落及步驟數，不以含糊的「快速看一下」降低預期透明度。
- 主要按鈕：`開始完整導覽`
- 次要按鈕：`稍後再看`

選擇開始後依序進行：

1. 品牌與目前工作區。
2. 左側主選單全部可用入口。
3. 可展開子選單及角色專屬入口。
4. 使用者身份與登出。
5. 頁首共同操作。
6. 版本更新入口。
7. 通知中心。
8. 固定操作教學入口。
完成第 8 步後立即關閉導覽並固定留在可操作的工作總覽，不接續顯示首頁導覽封面。即使使用者登入前原本要前往其他頁面，也不在此時自動跳回；首頁詳細導覽留待之後第一次重新進入首頁，或由固定問號入口主動開啟。

### 4.2 第一次進入任一頁面

頁面 DOM、角色權限及主要資料均穩定後，自動開啟該頁導覽封面；不得在載入骨架、權限尚未套用或按鈕尚未渲染時提前定位。

封面需顯示：

- 頁面名稱與用途。
- 本次會介紹的區段數與總步驟數。
- 是否包含會修改、發送、下載或刪除正式資料的功能說明。
- `開始完整導覽`、`稍後再看`。

導覽開始後按頁面工作順序分段：

1. 認識頁面與資料來源。
2. 閱讀、搜尋、篩選及狀態辨識。
3. 主要操作與表單輸入。
4. 正式送出、下載、完成或結案。
5. 常見限制、角色邊界及下一步。

### 4.3 中斷、稍後與略過

- `稍後再看`：保留未開始或目前步驟，下次進入該頁仍會提示；同一工作階段不重複彈出，頁首顯示低干擾的「繼續本頁導覽」。
- 關閉進行中的導覽：保存目前段落與步驟，下次從同一步繼續。
- `略過本頁導覽`：需在次要選單明確選擇；不再自動打斷，但在操作教學中心列為「尚未完成」。
- `重新觀看`：不清除完成紀錄，除非使用者另外選擇「重設我的導覽進度」。

### 4.4 動態與條件功能

固定頁面導覽會先說明開啟投票、董顧確認、正式公告、結案與更正等操作的存在條件、資料影響及所在區段。播放時只保留目前角色與畫面上可見的步驟；尚未出現的條件控制會安全略過，不會讓整段卡死。使用者日後可由固定問號入口重看本頁，在條件成立後查看實際控制位置。

新增或重大改寫的功能會提升導覽內容版本，使既有使用者只需重新查看受版本影響的導覽，不會清除其他頁面的完成紀錄。

### 4.5 換屆與角色改變

- 任期日期不納入導覽身份。同一人下一屆仍為副主席或仍為會員委員時，視為熟悉使用者並沿用原進度。
- 同一人由副主席轉為會員委員，或由會員委員轉為副主席時，先播放一次目的角色的差異導覽，不重播完整全站教學。
- 共同頁面的 `completed`／`skipped` 狀態沿用；未完成進度不跨角色複製。目的角色新增且從未使用的專屬頁面仍維持第一次進入自動教學。
- 只有來源角色的全站導覽已完成才啟用差異模式；未看完或略過者在新角色下仍使用完整新手導覽。
- 差異導覽完成或略過後直接停留在可操作首頁，不接續首頁詳細導覽封面。
- 角色歷程只以姓名雜湊與角色識別保存在目前瀏覽器，不保存姓名明文、不讀寫正式換屆名單，也不跨裝置同步。

## 五、導覽元件與視覺語言

### 5.1 品牌一致性

導覽沿用現有工作台視覺基礎：

- 主色：酒紅 `#a91419` 及現有深淺紅階。
- 背景：暖白／暖灰 `#f4f3f0`、`#f7f5f3`。
- 文字：深灰 `#25272a`，次要文字使用既有灰階。
- 字體：`Noto Sans TC`。
- 卡片：白色表面、1px 暖灰框線、16–20px 圓角、克制的深色柔影。
- 導覽層需與首頁儀表板、案件中心及登入頁屬於同一產品，不另造一套藍紫色 SaaS 風格。

### 5.2 聚焦層

- 使用固定全畫面遮罩及真正透明的聚焦開口，不以巨大外陰影粗糙模擬。
- 遮罩建議為深暖灰黑、約 62–70% 透明度；仍能辨認頁面脈絡，但視線只落在目標元件。
- 聚焦開口依目標原始圓角自動調整，外圍保留 6–10px 呼吸距離。
- 使用暖白細框搭配極淡酒紅光暈；不使用黃色螢光筆、霓虹邊框或持續閃爍。
- 原始控制保持可見但在說明模式中不可被誤按；遮罩負責攔截點擊，不修改原按鈕的業務狀態。
- 介紹報告、表單區段或工作流程時，聚焦完整卡片／工作區；只有說明單一按鈕或單一步驟時才聚焦個別控制，不以孤立數字輸入框代替整份功能。
- 零寬高、尚未渲染或目前不適用的動態目標需安全略過或改用穩定的上層工作區，不得產生一條細線或無意義小框。

### 5.3 教學卡

桌面版教學卡包含：

- 上方小標：`FULIAN PRODUCT GUIDE`／`系統操作導覽`。
- 區段與總步驟，例如 `篩選與閱讀・7／18`。
- 18–22px 標題。
- 一段主要用途說明。
- 視需要顯示「使用時機」「按下後」「注意」三種簡短資訊，不堆疊長文。
- `上一步`、`下一步`／`完成導覽`、關閉與更多選單。
- 細緻的段落進度線，不使用獎章、分數、煙火或遊戲化圖示。
- 進度線、更多選單及省略號均受教學卡邊界約束；更多選單開啟後，點擊卡片其他空白處即關閉，Escape 第一次只收合選單、第二次才中斷導覽。

尺寸原則：

- 桌面寬度約 360–400px，依內容自動增高但不得遮蔽目標。
- 與目標保持至少 16px 間距，優先放在可保留最多畫面脈絡的位置。
- 空間不足時改靠近視窗邊緣，不得縮成難讀的小泡泡。

### 5.4 動態效果

- 位置切換使用約 180–220ms 的淡入、位移及遮罩過渡。
- 不使用彈簧、彈跳、旋轉、脈衝或拖慢閱讀的裝飾動畫。
- 自動捲動只在目標不完整可見時發生，並在目標四周保留安全距離。
- 完整遵守 `prefers-reduced-motion: reduce`，改為立即切換且不平滑捲動。

### 5.5 手機與平板

- 手機使用底部教學面板，不把桌面浮卡硬縮成遮住目標的狹小氣泡。
- 面板原則上不超過可用高度 45%；長內容允許面板內捲動。
- 目標自動定位在面板上方可見區域。
- 聚焦框下緣保留在底部面板上方，不被面板覆蓋；超過一個螢幕高度的完整工作區以目前可見範圍呈現。
- 介紹主選單時自動開啟抽屜；完成該段後恢復原狀。
- 支援瀏海、安全區、橫向模式及軟鍵盤開啟狀態。

## 六、互動與安全原則

1. 導覽預設為「說明模式」：使用者按下一步閱讀，不直接操作被聚焦的正式控制。
2. 展開選單、切換唯讀分頁或開啟說明區可由導覽暫時完成；任何會寫入、送出、下載、發送、刪除或結案的動作一律不得由導覽代按。
3. 導覽為了展示而暫時改變的純畫面狀態，在結束或中斷後應還原。
4. 使用者原本輸入的表單內容、捲動位置與開啟中的安全對話框不得被覆蓋或清除。
5. 若目標因角色、資料或版本不存在，跳過該條件步驟並持續導覽；開發環境需提出明確警告，不得讓整段卡死。
6. 正式刪除、公告、投票、結案、換屆、帳密與 API Key 等功能，說明卡需清楚標示資料影響，但不能顯示任何真實秘密或會員敏感內容。
7. 公開回饋與公開投票頁僅說明當次必要操作，不揭露登入工作台、內部票向或不屬於填寫者的資料。

## 七、無障礙與鍵盤規格

- 導覽封面使用原生 `dialog` 或等效且完整的 modal 行為。
- 開啟時焦點進入導覽卡，`Tab`／`Shift+Tab` 留在卡片內，`Escape` 可安全中斷。
- 關閉後焦點回到啟動「操作教學」的按鈕，或回到合理的工作位置。
- 每一步透過 live region 宣告頁面、段落、步驟、標題與目標控制名稱。
- 聚焦框不是唯一線索；教學卡需以文字說明目標名稱。
- 所有文字、按鈕、焦點框及遮罩後目標均需保持足夠對比。
- 導覽不得因單純鍵盤聚焦某欄位而自行打開，避免反覆奪走焦點。

W3C 對 modal dialog 的焦點移入、焦點循環、Escape 關閉及關閉後焦點回復有明確規範；本功能的封面與中斷對話框須以此為最低標準：<https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/>。

## 八、教學內容寫作規格

每個導覽步驟應回答與該控制最相關的內容：

1. 這是什麼。
2. 何時使用。
3. 按下或填寫後會發生什麼。
4. 是否影響正式資料。
5. 使用者下一步去哪裡。

文字規則：

- 標題使用畫面上的正式名稱，不自創第二套稱呼。
- 一個步驟只講一個動作或一組同目的欄位。
- 主要說明以 45–90 個中文字為原則；需要更多內容時改為「查看詳細說明」，不讓教學卡變成文件頁。
- 不解釋已在制度課程完整教授的歷史與制度背景，只說明操作所需的最小判斷。
- 使用「會建立案件」「只保存草稿」「會正式發送 LINE」「不會改變會員主檔」等具體結果，不使用「處理」「執行」等模糊動詞。
- 禁止指控性語言；涉及會員資料與處置時提醒人工確認與權限邊界。

## 九、角色與身份分流

### 副主席

介紹完整日常管理、案件分工、回饋門檻、開票、董顧確認、公告、結案、資料更新、分析審閱、通知及副主席資源。

### 會員委員

聚焦自己的工作、訪談、進度、回饋、投票、點名、月會與可查看的會員關懷內容；不顯示或提及無權操作的副主席區段。

### Admin

完全排除。Admin 是系統設計與維護者，不建立導覽身份、不保存導覽進度、不載入工作頁導覽程式或樣式，首頁也會移除操作教學入口。

### 公開填寫者

只在 `public-feedback.html` 與 `public-vote.html` 提供短而完整的當頁教學，不建立登入者身份推論，也不顯示內部功能地圖。

## 十一、進度與版本模型

v1.1.0 每筆本機進度包含：

- 由 `userId`、姓名與角色產生的去識別雜湊鍵；儲存鍵不直接包含姓名。
- `role`。
- `guideId`：例如 `global-shell`、`page:index`、`page:case-board`、`feature:case-close`。
- `guideVersion`。
- `status`：`not_started`、`in_progress`、`completed`、`skipped`。
- `sectionId`、`stepId`。
- `startedAt`、`updatedAt`、`completedAt`。

保存原則：

1. v1.1.0 使用 localStorage 保存非敏感觀看狀態；副主席、每位會員委員與公開填寫頁各自隔離。
2. 不保存畫面內容、表單值、會員姓名、案件內容、投票內容、Token 或 API Key。
3. Admin 不建立任何進度資料。
4. 版本升級只讓該份重大改寫導覽重新成為待看，不清除其他頁面的完成紀錄。
5. 目前進度以裝置為範圍；未來若需要跨裝置續看，才另行以非敏感後端欄位同步。
6. 同一姓名的本機角色歷程另以去識別雜湊鍵保存，用來判斷同角色續任或副主席／會員委員互換；不把任期日期或正式名單寫進導覽資料。
7. 角色互換時只繼承來源角色已完成或已略過的逐頁狀態，不繼承進行中狀態，也不把全站完成狀態直接當成新角色已看；差異導覽完成後才將新角色全站教學標為完成。

## 十二、建議技術架構

導覽採全站共用、資料驅動，不在每個頁面複製一套流程：

- `core/onboarding-domain.js`：角色、版本、進度、條件步驟及完成判定的純邏輯。
- `assets/js/onboarding.js`：遮罩、定位、捲動、鍵盤、響應式與生命週期引擎。
- `assets/js/onboarding-guides.js`：全站與首頁的角色化導覽定義。
- `assets/js/onboarding-page-guides.js`：17 個工作頁與副主席課程頁的資料驅動定義。
- `assets/js/onboarding-public-guides.js`、`onboarding-public-bootstrap.js`：兩個免登入公開頁的最小必要導覽與匿名身份。
- `assets/css/onboarding.css`：唯一導覽視覺元件與響應式規格。
- HTML 使用穩定的 `data-guide-id`，不得依脆弱的第幾個子元素或純文字定位。
- 動態產生的控制在渲染時帶入穩定 `data-guide-id`、角色與狀態資訊。
- `workspace-nav.js` 統一加入操作教學入口，首頁另接既有桌面側欄。

導覽根節點掛在 `body` 最外層，以獨立圖層管理遮罩、聚焦框、教學卡及 live region；不得任意提高原業務按鈕的 z-index，以免破壞既有 sticky header、抽屜、AI 助手、modal 與 toast。

## 十四、測試與驗收標準

### 覆蓋

- 每個可見可操作控制均為 `covered`、`grouped`、`conditional` 或有理由的 `exempt`。
- 每個導覽目標 ID 唯一，且在適用角色與狀態下能找到。
- 新增按鈕若未登記導覽或豁免，測試應失敗或稽核應明確報錯。

### 視覺

- 驗證桌面 1440×900、一般筆電、平板及 390×844 手機尺寸。
- 教學卡不得遮住聚焦目標、頁面主標題或必要的下一個操作。
- 長文字、長姓名、放大字級及瀏覽器縮放後仍可使用。
- 與首頁、案件頁、表單、modal、抽屜、通知、AI 助手及 toast 的圖層不衝突。

### 互動

- 第一次進入自動出現；完成後不重複打斷。
- 中斷後回到正確步驟。
- 重看不破壞完成狀態；重設只影響目前使用者的教學進度。
- 上一步、下一步、關閉、Escape、Tab、Shift+Tab 及手機返回行為正確。
- 目標消失、資料為空或載入失敗時不會卡住整頁。

### 權限與資料安全

- 會員委員導覽不出現副主席／Admin 專屬內容。
- 導覽過程不得送出任何案件、投票、公告、LINE、Email、結案、換屆、帳密或 API Key 請求。
- 測試只使用去識別化資料，不保存畫面內容或會員敏感資訊。

### 使用者驗收

由第一次接觸系統的人完成下列任務：

1. 看完全站導覽後能直接操作首頁並指出每個主選單入口的用途；另開啟首頁導覽時能辨識首頁各工作區。
2. 第一次進入案件中心後，能找到指定案件、辨識階段並說出下一步。
3. 能自行中斷、繼續及重看本頁導覽。
4. 能分辨只保存草稿、正式送出、正式發送及不可逆操作。
5. 不需開啟制度課程，也能完成系統介面的基本操作。

## 十五、明確禁止

- 不購買或直接套用帶有既定外觀的廉價導覽套件。
- 不用 Emoji、卡通吉祥物、彩色獎章或慶祝動畫掩飾資訊層級不足。
- 不把完整制度文件貼進教學卡。
- 不因導覽而複製任何業務規則到頁面腳本。
- 不讓背景按鈕在說明模式中可被誤觸。
- 不用固定座標定位，也不假設所有人的螢幕、字級與資料長度相同。
- 不以「導覽能從第一步跑到最後一步」冒充完整覆蓋或成功理解。
- 不在整套導覽尚未完成驗收前，讓半成品自動打斷正式使用者。
